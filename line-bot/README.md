# 工程図 LINE Bot セットアップガイド

LINE で決まった言葉を送ると、工程図の最新情報を文字で返信する仕組みです。
毎日決まった時刻に、進捗をまとめた**定時報告**を自動で送ることもできます。
Google Apps Script（GAS）で動くため、**クレジットカード登録なし・無料**で使えます。

所要時間の目安：**30〜40分**（初回のみ）

---

## できること

| 送る言葉 | 返ってくる内容 |
|---|---|
| 本日納期 | 今日が納期の未完了の視点（＋納期を過ぎている未完了） |
| 明日納期 | 明日が納期の未完了の視点 |
| 今週納期 | 今日〜今週日曜が納期の未完了の視点（＋納期超過） |
| 来週納期 | 来週月曜〜日曜が納期の未完了の視点 |
| 全体納期 | 納期が決まっている全ての未完了の視点（日付順） |
| 案件一覧 | 進行中の案件（会社別・全体納期・視点・担当・完了見込み） |
| スケジュール | 今日の担当者別の作業予定（時刻つき） |
| 明日のスケジュール | 明日の担当者別の作業予定 |
| スケジュール 山田 | 担当者名で絞り込み（名前の一部でOK） |
| 進捗報告 | 定時報告と同じ内容を今すぐ表示（通数を使わない） |
| ヘルプ | 使い方の一覧 |

- 「完了見込み」「スケジュール」は、アプリの画面と同じ計算で出しています。
- 上の言葉以外には反応しません（グループの普段の会話の邪魔をしません）。
- **合言葉で登録したトーク／グループにだけ**答えます。知らない人が Bot を友だち追加しても、案件情報は見えません。

## 定時報告（毎日決まった時刻に自動で送信）

登録済みのトーク／グループで次の言葉を送ると設定できます。

| 送る言葉 | 内容 |
|---|---|
| 定時報告オン | このトークに定時報告を送る（最初は毎日8時ごろ） |
| 定時報告オフ | このトークへの定時報告を止める |
| 定時報告時刻 8 | 送る時刻を変える。`定時報告時刻 8,17` のように1日3回まで（全トーク共通） |
| 定時報告 | 今の設定と、今月の残り送信数・あと何回送れるかを表示 |

報告の中身：

```
【工程図 進捗報告】10/20(火) 08:03時点
進行中 4案件・視点6

■ 本日納期（1件）
 ・渋谷マンション IN1（山田） 見込み 10/20 15:00
■ 納期超過（未完了）（1件）
 ・田中邸 IN2（グエン） 納期10/19(月)
■ 納期に遅れる見込み（1件）
 ・新宿オフィス EX1（佐藤） 納期10/21(水)→見込み10/22(木)
■ 明日納期（1件）
■ 10/19(月)以降の完了（1件）
 ・渋谷マンション EX1（佐藤） ホワイト・カラー →視点完了
■ 本日の予定（担当者別）
 ・佐藤 8.0h：新宿オフィス EX1
 ・山田 6.0h：渋谷マンション IN1
```

- 「以降の完了」は**前営業日から**（月曜なら金曜または営業する土曜から）の完了です。中止した作業は入りません。
- **休業日（日曜・祝日・休みの土曜）は送りません**。休業日も送りたいときは、スクリプト プロパティに `REPORT_ON_HOLIDAYS` = `true` を追加します。
- 時刻は Google の仕組み上、**指定した時刻の前後15分ほど**のどこかで届きます。時刻は**ベトナム時間**です（工程図連携シートと同じ）。
- 今月の残り送信数が足りないときは送りません。残りが少なくなると報告の最後に注意書きが付きます。

### 定時報告で使う通数（ここだけ無料枠を使います）

質問への返信と違い、Bot から自分で送るメッセージは無料プランで**月200通まで**（超えた分は買えず、翌月まで送れません）。
数え方は **「1回送るごとに、送り先のトークの人数ぶん」** です（吹き出しの数は関係ありません）。

| 送り先 | 1回の報告 | 毎日1回（営業日 約24日） | 毎日2回 |
|---|---|---|---|
| 個人トーク（1人） | 1通 | 約24通 ✅ | 約48通 ✅ |
| 5人のグループ | 5通 | 約120通 ✅ | 約240通 ❌ 超える |
| 8人のグループ | 8通 | 約192通 ✅（ぎりぎり） | ❌ 超える |

> グループで使うなら**1日1回**がおすすめです。「定時報告」と送ると、今月あと何回送れるかを確認できます。
> 報告の内容を追加で見たいときは「進捗報告」と送れば、通数を使わずに同じ内容が見られます。

## 無料で使える範囲（1日の目安）

| サービス | 制限 | この Bot での目安 |
|---|---|---|
| LINE（Messaging API） | 無料プランは「こちらから送る」メッセージが月200通まで。**質問への返信（応答メッセージ）は通数に数えられず無料・無制限** | 質問への返信は**通数の心配なし**。定時報告だけ通数を使う（上の表を参照） |
| Google Apps Script（無料の Google アカウント） | 外部への通信が **1日20,000回** まで | 1回の質問で3回使うので、**1日 約6,000回** まで |
| Firebase（Firestore の読み取り） | 無料枠はプランによって異なります（Spark プランなら **1日50,000件**） | 1回の質問で「未完了のタスク数＋5件」を読みます。例：未完了300件なら1回305件 → 1日 約160回（アプリ自体の読み取りと共有） |

> 実際の読み取り件数は Firebase コンソール →「使用量と請求額」で確認できます。
> チームで1日数十回使う程度なら、どれも余裕で無料の範囲に収まります。

## Step 1. LINE 公式アカウントを作る（10分）

1. https://entry.line.biz/ から **LINE公式アカウント** を作成（無料の「コミュニケーションプラン」でOK）
2. LINE Official Account Manager（管理画面）を開き、右上の **設定** →
   **Messaging API** → **Messaging APIを利用する** をクリック
   - プロバイダーは新規作成でOK（名前は何でも可。例：`工程図`）
3. 同じく **設定** → **応答設定** を開き、次のように設定
   - 応答メッセージ：**オフ**
   - Webhook：**オン**
4. グループで使う場合：**設定** → **アカウント設定** →
   「グループ・複数人トークへの参加を許可する」を **許可する**
5. https://developers.line.biz/console/ を開き、作ったチャネル → **Messaging API設定** タブ →
   一番下の **チャネルアクセストークン（長期）** の「発行」を押し、表示された長い文字列をメモ帳に控える

## Step 2. Google Apps Script に Bot を入れる（15分）

> **必ず Firebase のオーナーの Google アカウント（kei.n412@gmail.com）で操作してください。**
> Bot はこのアカウントの権限で工程図のデータを読みます。

1. https://script.google.com/ を開き、**新しいプロジェクト** をクリック
2. 左上の「無題のプロジェクト」をクリックして名前を `工程図LINE Bot` に変更
3. エディタに最初から入っている `function myFunction() {...}` を**全部消す**
4. GitHub の [`line-bot/dist/Code.gs`](./dist/Code.gs) を開き、右上の「Raw」または
   コピーボタンで**全文をコピー**して、エディタに貼り付ける → 💾（保存）
5. 左の ⚙️ **プロジェクトの設定** →
   「**appsscript.json マニフェスト ファイルをエディタで表示する**」にチェック
6. 左の `<>` **エディタ** に戻り、`appsscript.json` を開いて中身を全部消し、
   [`line-bot/appsscript.json`](./appsscript.json) の内容を貼り付けて保存
7. ⚙️ **プロジェクトの設定** → 一番下の **スクリプト プロパティ** →
   「スクリプト プロパティを追加」で次の2つを登録して保存

   | プロパティ | 値 |
   |---|---|
   | `LINE_CHANNEL_ACCESS_TOKEN` | Step 1-5 で控えたチャネルアクセストークン |
   | `REGISTER_CODE` | 登録用の合言葉（例：`koutei-2026-sakura`。**推測されにくい言葉**にしてください） |

8. **動作テスト**：エディタ上部の関数選択で `testCommands` を選んで **実行**（定時報告で使う「時刻トリガー」の権限もここで承認されます）
   - 初回は「承認が必要です」→ **権限を確認** → アカウントを選択
   - 「Google はこのアプリを確認していません」と出たら **詳細** →
     「工程図LINE Bot（安全ではないページ）に移動」→ **許可**
     （自分で作ったスクリプトなので問題ありません）
   - 下の **実行ログ** に「本日納期」「案件一覧」などの返信文が表示されれば成功

## Step 3. ウェブアプリとして公開し、LINE とつなぐ（5分）

1. エディタ右上の **デプロイ** → **新しいデプロイ**
2. 左の ⚙️（種類の選択）→ **ウェブアプリ**
3. 次のように設定して **デプロイ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec`）をコピー
5. LINE Developers コンソール → チャネル → **Messaging API設定** →
   **Webhook URL** に貼り付けて「更新」→ **Webhookの利用** を **オン**
   - 「検証」ボタンでエラー（302 など）が出ることがありますが、GAS の仕様によるもので**問題ありません**。次の Step で実際に返信が来れば OK です。

---

## Step 4. LINE で使い始める

1. LINE Developers の **Messaging API設定** にある QR コードで Bot を友だち追加
   （グループで使う場合は、そのグループに Bot を招待）
2. トーク（またはグループ）で「**登録 合言葉**」と送信（例：`登録 koutei-2026-sakura`）
3. 「登録しました」と返ってきたら完了。「**本日納期**」などを送ってみてください

- 登録はトーク／グループごとに1回だけです。
- やめたいときは、そのトークで「**登録解除**」と送信します。
- 全ての登録をまとめて消したいときは、GAS エディタで `clearRegisteredIds` を実行します。
- 定時報告を使うなら、送りたいトークで「**定時報告オン**」と送信します（上の「定時報告」の章を参照）。

## 定時報告の機能を追加する前の Bot を使っている場合（2026年10月の更新）

前回の Bot から更新するときは、次の手順で入れ替えてください（Webhook URL は変わりません）。

1. GAS エディタの `コード.gs` を最新の [`dist/Code.gs`](./dist/Code.gs) に、`appsscript.json` を最新の [`appsscript.json`](./appsscript.json) に貼り替えて保存
   （時刻トリガーを使う権限の追加と、時刻をベトナム時間にする変更が入っています）
2. エディタで `testCommands` を実行し、**新しい権限を承認**（承認画面が出なければそのままでOK）
3. **デプロイ** → **デプロイを管理** → ✏️（編集）→ バージョン：**新バージョン** → **デプロイ**
4. 報告を送りたいトークで「**定時報告オン**」と送信

## Bot を新しくするとき（アプリ側の計算が変わったときなど）

`line-bot/dist/Code.gs` は、アプリをビルドするたびに自動で作り直されます。
Bot に反映したいときだけ、次の手順で入れ替えます（Webhook URL は変わりません）。

1. GAS エディタの `コード.gs` の中身を全部消し、最新の `line-bot/dist/Code.gs` を貼り付けて保存
2. **デプロイ** → **デプロイを管理** → ✏️（編集）→ バージョン：**新バージョン** → **デプロイ**

> ⚠️「新しいデプロイ」を押すと URL が変わってしまいます。更新は必ず「**デプロイを管理**」から行ってください。

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 何を送っても返事がない | LINE の応答設定で「Webhook：オン」「応答メッセージ：オフ」か／Webhook URL が正しいか／GAS の「実行数」画面にエラーが出ていないか |
| 「まだ登録されていません」と返ってくる | そのトークで「登録 合言葉」を送ったか（グループと個人トークは別々に登録が必要） |
| 「データの取得に失敗しました（Firestore 403 …）」 | GAS を Firebase オーナーのアカウントで作ったか／`appsscript.json` を貼り付けたか。貼り付け後は `testCommands` を再実行して権限を承認し直す |
| 「Cloud Firestore API has not been used in project …」 | GAS の ⚙️ プロジェクトの設定 →「Google Cloud Platform（GCP）プロジェクト」を Firebase のプロジェクト（`koutei-zu`、番号は Firebase コンソールのプロジェクト設定に表示）に変更する。「OAuth 同意画面」の設定を求められたら、案内に従って「外部」を選び、アプリ名とメールアドレスだけ入力すればOK |
| 日付が1日ずれる・定時報告の時刻がずれる | `appsscript.json` の `"timeZone"` を実際に使う地域に合わせる（今はベトナム：`Asia/Ho_Chi_Minh`。日本にするなら `Asia/Tokyo`）。変えたら LINE で「定時報告時刻 8」などと送り直してトリガーを作り直す |
| 定時報告が届かない | 「定時報告」と送って「このトーク：オン」か・今月の残り通数があるかを確認／その日が休業日でないか／GAS の「トリガー」画面に `sendScheduledReport` があるか／GAS の「実行数」画面のエラー（データ取得に失敗したときは Google からオーナーにメールが届きます） |
| 定時報告を試しに送りたい | GAS エディタで `sendReportNow` を実行（通数を使います）。中身だけ見たいなら LINE で「進捗報告」 |

## 仕組み（参考）

```
LINE で「本日納期」と送信
  → LINE が GAS のウェブアプリ（doPost）へ通知
  → GAS が Firestore から未完了タスク・設定を読み込む
  → アプリと同じスケジュール計算（src/lib/schedule.js）で集計
  → LINE の返信 API で文字を返す

定時報告：GAS の時刻トリガーが sendScheduledReport を実行
  → 同じ集計で報告文を作る → 残り通数を確かめて LINE のプッシュ API で送る
```

- `bot.js` … Bot 本体（言葉の判定・返信文の組み立て）
- `build.mjs` … `src/lib` の計算ロジックと `bot.js` を1つの `dist/Code.gs` にまとめるスクリプト
- `dist/Code.gs` … GAS に貼り付けるファイル（自動生成・直接編集しない）
- `appsscript.json` … GAS の設定（タイムゾーン・必要な権限）
- `test/bot.test.mjs` … LINE・Firestore・GAS の偽物の上で Bot を動かすテスト（`npm test` に含まれる）
