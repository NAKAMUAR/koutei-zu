# Telegram 連携セットアップ手順

作成: 2026-08-24 / 版: 1.1 / 対象: `bot/worker.js` / 設計: `docs/08_チャット連携（外部AIエージェント）設計.md`

スマホの Telegram から工程図の**案件登録**と**状況確認**ができるようにする手順書。
専門知識は不要。上から順にやれば完了する。

> **Discord を使いたい場合は `docs/10_Discord連携セットアップ手順.md` を参照してください。**
> `bot/worker.js` は Telegram と Discord の両方に対応しており、**1つの Worker で両方同時に使えます**。

- **所要時間の目安**：40〜60分（メールの確認待ちを含む）
- **費用**：0円（Cloudflare・Telegram・Firebase の無料枠で足りる）
- **AI（Gemini）は使わない**ので、API キーも利用回数の制限も不要

> **既存の Bot には一切影響しません。** 今回は新しい Telegram Bot と新しい Cloudflare Worker を作ります。
> 今動いている Worker（Webページ生成のBot）はそのままで構いません。

---

## 0. 全体の流れ

| 手順 | 何をするか | 場所 |
|---|---|---|
| 1 | Bot 用の Google アカウントを作る | Google |
| 2 | そのアドレスを Firebase に登録する | Firebase |
| 3 | 工程図アプリのメンバーに追加する | 工程図アプリ |
| 4 | Telegram の Bot を作る | Telegram |
| 5 | 自分の chat id を調べる | ブラウザ |
| 6 | Cloudflare で Worker を作る | Cloudflare |
| 7 | KV（記憶領域）を作ってつなぐ | Cloudflare |
| 8 | 設定値（シークレット）を登録する | Cloudflare |
| 9 | コードを貼り付けて公開する | Cloudflare |
| 10 | 確認メールを送って開く | ブラウザ＋メール |
| 11 | 疎通確認する | ブラウザ |
| 12 | Telegram とつなぐ | ブラウザ |

**手順10〜12はブラウザでURLを開くだけです。** コマンド入力は一切ありません。

## 1. Bot 用の Google アカウントを作る

工程図のデータは「許可されたメールアドレス」しか開けない設定になっています。Bot にも1つアカウントが必要です。

1. Google アカウントを新規作成する（例：`koutei-bot@gmail.com`）
2. パスワードは**長めのランダムな文字列**にして、パスワード管理ツール等に控える

> ご自身の `kei.n412@gmail.com` を使い回すことは避けてください。パスワードを Cloudflare に預けることになるためです。

**メモ欄**

- Bot のメールアドレス： `______________________`
- Bot のパスワード： （安全な場所に保管）

---

## 2. Firebase に Bot アカウントを登録する

1. [Firebase コンソール](https://console.firebase.google.com/) を開き、プロジェクト **koutei-zu** を選ぶ
2. 左メニュー **構築 > Authentication** を開く
3. **Sign-in method**（ログイン方法）タブ → プロバイダに **メール / パスワード** が無ければ追加し、**有効**にして保存
   - すでにある「Google」はそのままにしておくこと（工程図アプリのログインに使っています）
4. **Users**（ユーザー）タブ → **ユーザーを追加**
   - メール：手順1で作ったアドレス
   - パスワード：手順1で決めたパスワード
5. 追加できたら完了（この時点ではまだ「メール確認」は済んでいません。手順10で行います）

---

## 3. 工程図アプリのメンバーに追加する

1. PC で工程図アプリ https://nakamuar.github.io/koutei-zu/ を開き、**ご自身の Google アカウント**でログイン
2. 設定パネルの **メンバー管理** を開く
3. 手順1のアドレスを追加して保存

> メンバーリストを編集できるのはオーナー（`kei.n412@gmail.com`）だけです。

---

## 4. Telegram の Bot を作る

1. Telegram で **@BotFather** を開く
2. `/newbot` を送る
3. 表示名を入力（例：`工程図`）
4. ユーザー名を入力（**末尾が `bot` である必要があります**。例：`koutei_zu_bot`）
5. **トークン**が表示されるので控える（`123456789:AAE...` のような文字列）

**メモ欄**

- TELEGRAM_TOKEN： `______________________`

> このトークンは**パスワードと同じ扱い**です。GitHub などに貼らないでください。

---

## 5. 自分の chat id を調べる

1. 手順4で作った Bot をトークの一覧から開き、**何かメッセージを送る**（`/start` でOK）
2. ブラウザで次のURLを開く（`<TOKEN>` は手順4のトークンに置き換え）

```
https://api.telegram.org/bot<TOKEN>/getUpdates
```

3. 表示された文字の中から `"chat":{"id":8991512381,` のような部分を探し、**数字**を控える

> 既存の Bot で使っている `8991512381` と同じ値になるはずです（Telegram のユーザーIDは Bot が変わっても同じため）。念のため確認してください。

**メモ欄**

- MY_CHAT_ID： `______________________`

---

## 6. Cloudflare で Worker を作る

1. [Cloudflare ダッシュボード](https://dash.cloudflare.com/) を開く
2. 左メニュー **Workers & Pages** → **Create**（作成）→ **Worker**
3. 名前を付ける（例：`koutei-zu-bot`）→ **Deploy**（デプロイ）

これで `https://koutei-zu-bot.<あなたのアカウント名>.workers.dev` のようなURLができます。控えておいてください。

**メモ欄**

- Worker の URL： `______________________`

> Cloudflare の画面の名称は変わることがあります。「Worker を新規作成して一度デプロイする」ができればOKです。

---

## 7. KV（記憶領域）を作ってつなぐ

Bot が「ログイン情報」「入力の途中経過」を一時的に覚えておくための場所です。

1. 左メニュー **Storage & Databases**（ストレージとデータベース）→ **KV**
2. **Create**（作成）→ 名前を付ける（例：`koutei-bot-state`）→ 作成
3. 手順6の Worker を開く → **Settings**（設定）→ **Bindings**（バインディング）→ **Add**（追加）
4. 種類は **KV namespace** を選び、
   - **Variable name（変数名）**：`STATE` ← ★この名前でないと動きません
   - **KV namespace**：さきほど作ったもの
5. 保存

> 既存 Bot の `COUNTER` を使い回すこともできますが、**新しく作ることをおすすめします**（データが混ざらないため）。

---

## 8. 設定値（シークレット）を登録する

Worker を開く → **Settings**（設定）→ **Variables and Secrets**（変数とシークレット）→ **Add**（追加）。
**種類は必ず「Secret」を選んでください**（「Text」だと画面に値が見えてしまいます）。

次の10個を登録します。

| 名前 | 入れる値 |
|---|---|
| `TELEGRAM_TOKEN` | 手順4のトークン |
| `WEBHOOK_SECRET` | 自分で決めるランダムな文字列（※下の注意を参照） |
| `MY_CHAT_ID` | 手順5の数字 |
| `FIREBASE_API_KEY` | `AIzaSyA2iQimhNq11ElsLb57qq3fuKx_3OGIcPE` |
| `FIREBASE_PROJECT_ID` | `koutei-zu` |
| `FIRESTORE_DATABASE_ID` | `default` |
| `WORKSPACE_ID` | `liebe-asia-team` |
| `BOT_EMAIL` | 手順1のアドレス |
| `BOT_PASSWORD` | 手順1のパスワード |
| `TZ_OFFSET` | `9`（日本時間。ベトナム拠点の時刻で登録日を扱いたい場合は `7`） |

**`WEBHOOK_SECRET` の注意**

- 使える文字は **半角英数字と `_` `-` だけ**（Telegram の制約）。記号や日本語は使えません
- 30文字程度のランダムな文字列にしてください（例：`kzu-8f3a91c47be25d06af1b9e3c7d`）
- **このあと手順10〜12でURLの一部として使う**ので、控えておいてください

> `FIREBASE_API_KEY` は公開前提の値なので、秘密ではありません（工程図アプリのソースにも書かれています）。

**メモ欄**

- WEBHOOK_SECRET： `______________________`

---

## 9. コードを貼り付けて公開する

1. Worker の画面で **Edit code**（コードを編集）を開く
2. 表示されているコードを**全部消す**
3. このリポジトリの **`bot/worker.js` の中身を全部コピーして貼り付ける**
   - GitHub で見る場合： https://github.com/NAKAMUAR/koutei-zu/blob/main/bot/worker.js
4. **Deploy**（デプロイ）

> 追加のインストールやビルドは不要です。1ファイルで完結しています。

---

## 10. 確認メールを送って開く　★一番の詰まりどころ

工程図のセキュリティ設定は「**メール確認が済んだアドレス**」しか受け付けません。ここを飛ばすと動きません。

1. ブラウザで次のURLを開く（`<WORKER_URL>` と `<WEBHOOK_SECRET>` は自分の値に置き換え）

```
<WORKER_URL>/verify/<WEBHOOK_SECRET>
```

例： `https://koutei-zu-bot.example.workers.dev/verify/kzu-8f3a91c47be25d06af1b9e3c7d`

2. `{"ok":true, ...}` と表示されればメール送信成功
3. **Bot 用アドレスの受信箱**（手順1の Gmail）を開き、Firebase からの確認メールの**リンクをクリック**
4. 「メールアドレスが確認されました」と出れば完了

**うまくいかないとき**

| 表示 | 対処 |
|---|---|
| `ログイン失敗: INVALID_PASSWORD` | `BOT_PASSWORD` が違います |
| `ログイン失敗: EMAIL_NOT_FOUND` | 手順2のユーザー追加ができていません |
| `ログイン失敗: ...API key...` | `FIREBASE_API_KEY` を確認 |
| メールが届かない | 迷惑メールフォルダを確認。数分待ってもう一度URLを開く |

## 11. 疎通確認する

ブラウザで次のURLを開きます。

```
<WORKER_URL>/test/<WEBHOOK_SECRET>
```

成功するとこのように表示されます。

```json
{
  "ok": true,
  "手順": {
    "1_ログイン": "OK",
    "2_メール確認済み": "OK",
    "3_マスタの読み取り": "OK",
    "4_タスクの読み取り": "OK"
  },
  "会社数": 12,
  "担当者数": 8,
  "ステップ種類数": 7,
  "進行中タスク数": 43
}
```

**どこで止まったかが分かるようになっています。**

| 止まった場所 | 意味と対処 |
|---|---|
| `1_ログイン` で失敗 | `BOT_EMAIL` / `BOT_PASSWORD` が違う |
| `2_メール確認済み` が「まだです」 | 手順10のメールのリンクを開いていない |
| `3_マスタの読み取り` で 403 | Bot のアドレスが工程図の**メンバー管理**に入っていない（手順3） |
| `3_マスタの読み取り` で 404 | `FIREBASE_PROJECT_ID` / `FIRESTORE_DATABASE_ID` / `WORKSPACE_ID` の打ち間違い。特に **`FIRESTORE_DATABASE_ID` は `default`**（`(default)` ではない） |
| 会社数・担当者数が 0 | 工程図アプリのマスタが空。アプリ側で登録してください |

## 12. Telegram とつなぐ

ブラウザで次のURLを開きます。

```
<WORKER_URL>/init/<WEBHOOK_SECRET>
```

`{"setWebhook":{"ok":true...},"setMyCommands":{"ok":true...}}` と出れば完了です。
Webhook の登録と、**コマンドメニューの登録**が同時に行われます。

Telegram で Bot を開き、`/help` を送ってみてください。使い方が返ってきたら成功です。

## 13. 使い方

Telegram の入力欄の左にある **「/」ボタン**を押すと、コマンド一覧から選べます（覚える必要はありません）。

### 登録

```
/new
```

あとは**ボタンを押していくだけ**です。

```
会社は？        [TAMAZEN] [SUMUS] [（直接入力）]
案件名は？       ← ここだけ文字入力
視点は？        [EX1] [EX2] [EX3] [IN1] [IN2] [IN3] [（直接入力）]
担当は？        [ヤマダ] [タナカ] … [（直接入力）]
ステップ1の種類？ [ホワイト] [カラー] [ホワイト修正（無料）] …
制作時間は？     [1h] [2h] [4h] [8h] … [（直接入力）]
ステップを追加？  [ステップを追加] [納期の入力へ進む]
納期は？        [今週末(2026-08-28)] [来週末(2026-09-04)] [指定なし] [（直接入力）]

【この内容で登録しますか？】
…
        [登録する] [やめる]
```

**選択肢は工程図のマスタから自動で作られます。** そのため会社名・担当者名・ステップ種類は必ずアプリの値と一致し、打ち間違いが起きません。

- 制作時間の直接入力は `8` `8:30` `4.5` のいずれでもOK
- 納期の直接入力は `8/5` `2026-08-05` のいずれでもOK
  - **`8/5` のように月日だけ書いた場合、今年の日付がすでに過ぎていれば来年として解釈します。** 確認画面に解決後の日付が出るので、必ずそこで確認してください
- 途中でやめたいときは `/cancel`
- 30分放置すると入力内容は破棄されます

### 取り消し

```
/undo
```

直前に登録した案件を丸ごと削除します（24時間以内）。

### 確認

| コマンド | 内容 |
|---|---|
| `/status` | 進行中の案件一覧（会社別・残時間・納期） |
| `/status A棟` | その案件の詳細（視点・ステップごとの進捗） |
| `/due` | 納期が近い順 |
| `/who` | 担当者別の残作業 |
| `/who ヤマダ` | その人の案件内訳 |
| `/today` | 今日の予定（※下記参照） |
| `/help` | 使い方 |

日本語のコマンドも使えます：`/案件` `/状況` `/納期` `/担当` `/今日` `/取消` `/ヘルプ`

### `/today` について

**現在は使えません。** 「何日の何時に作業するか」という予定は工程図アプリが画面を開くたびに計算しているもので、データとして保存されていないためです（設計書 4-1）。

使えるようにするには、アプリ側に「計算結果を保存する仕組み」を追加する必要があります（設計書 改善案①・第3段階）。`/today` を送ると、その旨の案内が返ります。

## 14. 登録後の動き

- **PCで工程図アプリを開いていれば、数秒で画面に案件が出ます**（アプリがデータの変化を常に見張っているため）
- 優先順位は自動で会社ごとの末尾に入ります。並べ替えたいときはアプリでドラッグしてください
- **作業予定（何日の何時にやるか）の計算は、アプリを開いたときに行われます**
- 金額はBotからは登録しません。オフショア案件の金額はアプリの案件フォームで入力してください

## 15. うまく動かないときの確認表

| 症状 | 確認すること |
|---|---|
| Telegram に何を送っても無反応 | ① 手順12の `/init` を実行したか ② `MY_CHAT_ID` が手順5の値と一致しているか（違う人からのメッセージは全て無視されます） |
| 「エラーが発生しました：Firestore 403」 | Bot のアドレスがメンバー管理に入っているか。メール確認が済んでいるか |
| 「エラーが発生しました：Firestore 404」 | `FIRESTORE_DATABASE_ID` が `default` になっているか |
| 「Firebase ログイン失敗」 | `BOT_EMAIL` / `BOT_PASSWORD`。Bot のパスワードを変えた場合はここも直す |
| 会社や担当者のボタンが出ない | 工程図アプリのお客様マスタ・担当者マスタが空。アプリで登録してください |
| マスタを直したのにボタンに反映されない | 選択肢は5分間キャッシュされます。5分待つか、Worker を再デプロイしてください |
| ボタンを押しても「期限切れです」 | 30分以上放置した入力です。`/new` からやり直してください |
| 登録した案件がアプリに出ない | アプリを再読み込み。それでも出ない場合は「完了」タブも確認 |

原因が分からないときは、まず **`<WORKER_URL>/test/<WEBHOOK_SECRET>`** を開いてください。どの段階で失敗しているか分かります。

## 16. 安全に使うために

| 項目 | 内容 |
|---|---|
| 誰が使えるか | `MY_CHAT_ID` の本人だけ。他の人が Bot を見つけて話しかけても**完全に無視**します |
| なりすまし対策 | Telegram からの通信であることを `WEBHOOK_SECRET` で毎回確認しています |
| 秘密情報の置き場所 | Cloudflare の「Secret」のみ。**GitHub には絶対に入れないでください** |
| 外部AIへの送信 | **ありません。** Gemini などのAIは一切使っていません |
| Bot ができること | 工程図のデータの読み書きのみ（メンバーと同じ権限） |

### 定期的に確認したいこと

- Bot アカウントのパスワードを変えたら、Cloudflare の `BOT_PASSWORD` も更新する
- Bot を使わなくなったら、工程図アプリの**メンバー管理からアドレスを削除**する（それだけで一切アクセスできなくなります）

## 17. 技術メモ（開発者向け）

- コード：`bot/worker.js`（1ファイル・依存なし・ビルド不要）
- タスクのフィールド構成は `src/App.jsx` の `buildRecords` と揃えてある。**アプリ側のスキーマを変えたら `bot/worker.js` の `buildTasks` も更新すること**（設計書 第10.2章が両者の契約）
- `kanaNormalize` / `parseHM` / `fmtHM` / `resolveViewpointSteps` は `src/lib/utils.js` `src/viewpoint/viewpointUtils.js` からの移植。アプリ側を変えたらこちらも合わせる
- `hours` は**小数時間**（8時間 = `8`、4時間30分 = `4.5`）。分ではない
- `priority` は `99` で書き、アプリの `normalizePriorities()` が読み込み時に会社ごとへ振り直す
- Bot が作ったタスクには `createdVia: 'telegram'` と `externalId: 'tg::<ms>::<i>'` が入る
- 隠しエンドポイント（すべて `WEBHOOK_SECRET` で保護）
  - `/verify/<secret>` … 確認メールを送る
  - `/test/<secret>` … ログイン〜読み取りまでの疎通確認
  - `/init/<secret>` … Webhook とコマンドメニューを登録
