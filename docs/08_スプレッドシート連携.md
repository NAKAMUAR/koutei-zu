## 1. 全体の流れ

```
「工程図 エンジニア入力シート」（制作メンバーに共有）
   『入力シート』タブ：1視点1行
     会社コード（REN・RIC…）/ 案件番号 / 社外案件名 / サーバーリンク / 新規or修正 /
     視点（EX1・IN1・EXCB1・INCB1・EXM1・INM1・EXP1・INP1・VR1・VIDEO1…）/ パターン（A・B…）/ White / Color / pts / メモ
   『記入ルール/説明』タブ：書き方（日本語・ベトナム語）
        │  ① 30分ごとに自動で転記（変わりがあれば、その分だけ。記入途中の行は待つ。人が直した欄は上書きしない）
        ▼
「工程図連携」シート（管理者だけが見られる・別ファイル。エンジニアには共有しない）
   ・入力日：最初に転記した日を自動で記録
   ・会社コード＋案件番号 → 社内案件名「RIC.34」
   ・会社マスタ：RIC → 株式会社リックデザイン（エンジニアの会社コードのプルダウンもここから作る）
   ・案件マスタ：RIC.34 → 社外案件名・会社名・お客様担当者
   ・視点マスタ：EX → 区分「外観目線」・種類「パース」、EXM → 「外観モデル」「モデル」、VR → 種類「VR」（視点のプルダウンもここから作る）
   ・EX1 → 社外視点名「外観目線視点①」（区分＋視点＋丸数字）、パターンA → 「外観目線視点①_パターンA」
   ・自動判定がすべてできた行は「未送信」、足りない行は「要確認」
        │  ② 同じ30分ごとの自動実行で、「未送信」の行を自動登録（転記から25分待つ＝入力ミスを直す時間）
        │     「要確認」「更新あり」の行は、人が直して「工程図へ」にチェック → 次の自動実行で登録
        ▼
工程図（koutei-zu）
   ・White → 「ホワイト」、Color → 「カラー」、pts → 「人物＋添景合成」のステップ
   ・パース以外は1ステップ（写真合成 → 「写真合成」、モデル → 「モデル作成」、VR → 「VR制作」、動画 → 「動画制作」。時間は合計）
   ・「修正」の行 → 「修正」ステップとして同じ視点に追加
   ・種類（新規／追加／修正）は売上・帳票の「初回／追加／修正」として登録
   ・『会社マスタ』の会社が顧客マスタに無ければ、先に顧客マスタへ追加
        │
        ▼  工程図の既存機能
   スケジュールの自動反映 → 売上表の登録・集計 → 見積書・発注書・請求書の作成
   （金額は工程図の請求パネルで入力。顧客マスタに単価が無いため自動計算はしない）
```

工程図に登録したあとの担当者・優先度・完了時間・完了状態は工程図側が正で、シートからは上書きしません。
工程図側で削除したタスクは、再送信しても復活しません。

## 2. 最初に1回だけ行うこと

### 2-1. シートの置き場所と共有

- 管理者用の「工程図連携」と、エンジニア用の「工程図 エンジニア入力シート」は **別のファイル** です。
  - 「工程図連携」は **エンジニアには共有しない** でください。共有していなければ、入力シート側からは一切見えません（会社名・担当者などの紐づけ情報を含みます）。
  - 同じファイルの中でタブを「非表示」にする方法は使いません。編集できる人なら誰でも再表示できるためです。
- 「工程図 エンジニア入力シート」は、制作メンバー（エンジニア）に **編集** 権限で共有してください。
- スクリプトを動かす Google アカウント（kei.n412）に、次の2つの権限が必要です。
  1. 「工程図連携」の **編集** 権限
  2. 「工程図 エンジニア入力シート」の **編集** 権限（見出し・プルダウン・記入ルールを整えるため）
- kei.n412 は工程図の Firebase プロジェクトのオーナーなので、**Firebase 側の追加登録は不要** です。
- 30分ごとの自動実行は、「0. かんたん初期設定」を押したアカウント（kei.n412）の権限で動きます。

### 2-2. スクリプトの貼り付け

1. 「工程図連携」を開き、メニュー **拡張機能 → Apps Script** を開く。
2. 左の「コード.gs」の中身を全部消して、リポジトリの `sync/Code.gs` の内容を貼り付ける。
3. 左の歯車（プロジェクトの設定）→ **「appsscript.json」マニフェスト ファイルをエディタで表示** にチェック。
   エディタに戻ると `appsscript.json` が見えるので、中身を `sync/appsscript.json` の内容に置き換える。
4. 保存（フロッピーのアイコン）。
5. シートに戻って **再読み込み** すると、上のメニューに **「工程図連携」** が出ます。

### 2-3. かんたん初期設定（ボタン1回）

1. シートを再読み込みし、メニュー **工程図連携 → 0. かんたん初期設定（最初に1回だけ）** を押す。
2. 初回は「承認が必要です」と出るので、**権限を確認 → アカウントを選択**。
   「このアプリは Google で確認されていません」と出たら **詳細 → （安全ではないページ）に移動** を押して進めます（自作のスクリプトなので問題ありません）。
3. 承認が済んだら、もう一度 **0. かんたん初期設定** を押す。次をまとめて行い、結果を1つの画面で表示します。
   - 管理者シートを整える（『連携』に足りない列（入力日・新規or修正 など）を右端に追加・『案件マスタ』を作成・チェックボックスとプルダウン・『視点マスタ』に「社外名」列（空＝区分＋視点）・『会社マスタ』に「入力シートに出さない」列・『設定』に自動実行の項目・『使い方』）
     管理者が直したマスタの行（会社・視点のキーワード・区分・種類）は変えません。
   - 『設定』が旧「Project Schedule」を指したままなら、「工程図 エンジニア入力シート」の『入力シート』へ切り替える
   - エンジニア入力シートを整える（下の 2-4）
   - 工程図との接続テスト
   - 『会社マスタ』の会社のうち、工程図の顧客マスタに無い会社を追加する（表記だけ違う会社は追加せず「△」で知らせる。2-7）
   - 30分ごとの自動実行を設定する（✗ が1つでもあるときは設定しない）
4. すべて **✓** なら準備完了です。**✗** があれば、その行に書いてある対処をしてから、もう一度押してください（何度押しても安全です。列・タブ・顧客マスタの会社・自動実行が増えることはありません）。
   今回から自動実行（トリガー）の許可が増えたので、以前に承認していても、もう一度承認画面が出ます。

> メニューを押すのは **kei.n412 のアカウント**（工程図の Firebase オーナー）にしてください。別のアカウントで押すと接続テストが失敗することがあります（その場合は 2-6 の秘密鍵を設定）。

### 2-4. エンジニア入力シート（「0. かんたん初期設定」で整う内容）とエンジニアへの共有

「0. かんたん初期設定」（または メニュー「エンジニア入力シートを整える」）を押すと、エンジニア入力シートが次の形になります。何度押しても同じ結果です。

- 『入力シート』タブ
  - 2行目の見出しを **「日本語」＋改行＋「ベトナム語」** の2段にする（例「会社コード / Mã công ty」）。1列目の見出しが「社外案件名」になっていても、案件番号のすぐ左の列は「会社コード」として読み、見出しを直します。
  - 見出しに2か国語の注記（セルにマウスを乗せると出る説明）、1行目に案内（書き方は『記入ルール/説明』タブ）。
  - 3行目から下（1000行分）にプルダウンを付ける。見出しまでの2行は固定表示。
- 『記入ルール/説明』タブ：書き方・視点コード表・記入例を **日本語とベトナム語の併記** で書き直します（手で書いた内容は上書きされます）。
- 9/21 に配った古い書き方のタブ（『Untitled』など）には触りません。不要なら手で削除してください。

| 列 | 書き方 | 入力のしかた |
|---|---|---|
| 会社コード / Mã công ty | REN・RIC など | プルダウン（『会社マスタ』の案件コードの英字部分。「入力シートに出さない」にチェックした表記ゆれの行は出ない）。リストに無い値も入れられるが警告が出る |
| 案件番号 / Số dự án | 例 34 | 数字だけ（数字以外は入れられない）。会社コードと合わせて社内案件名「RIC.34」になる。番号は増え続けるのでリストではなく数字チェックにしている |
| 社外案件名 / Tên dự án | 例 マンション | 自由入力。『連携』の社外案件名（工程図の案件名）になる |
| サーバーリンク / Link thư mục | CG から始まる保存先フォルダのパス | 自由入力。会社名の推定にも使う |
| 新規or修正 / Mới / Sửa | その視点の初回依頼は「新規 / Mới」、2回目以降はすべて「修正 / Sửa」 | プルダウン（リスト以外は入れられない） |
| 視点 / Góc nhìn | 『視点マスタ』のキーワード＋番号。外観目線視点① EX1 / 内観目線視点① IN1 / 外観鳥瞰 EXCB1 / 内観鳥瞰 INCB1 / モデル（外観部）EXM1 /（内観部）INM1 / 外観写真合成 EXP1 / 内観写真合成 INP1 / VR1 / 動画 VIDEO1。①と末尾の数字は同じ | プルダウン（『視点マスタ』のキーワードごとに 1〜10、IN は 1〜20）。リストに無いコードも入れられる（その行は「要確認」になる） |
| パターン / Phương án | 同じ視点のパターン違いは A・B・C…（無ければ空） | プルダウン（A〜F） |
| White / Trắng | ホワイトパースまでの制作時間。モデルの行はモデル制作時間 | プルダウン（0〜10 は 0.5 刻み、11〜40）。リストに無い数字も入れられる |
| Color / Màu | 色付きパースまでの制作時間（White の時間は含めない） | 同上 |
| pts / Ghép ảnh | 写真合成・フォトショップ作業（人物・点景など）の時間 | 同上 |
| メモ / Ghi chú | 制作上の注意点 | 自由入力（『連携』の「元シート備考」に写る） |

- 依頼のたびに1行足します（過去の行は消さない）。同じ会社コード＋案件番号＋視点（パターン込み）が何回目かを数えて取込キーにします。
- **会社コード・案件番号・新規or修正・視点・時間（White / Color / pts のどれか）がそろった行だけ** 転記します。そろっていない行は「記入途中」として待ち、そろった後の転記で追加されます。
- 『記入ルール/説明』の視点コード表は『視点マスタ』から作ります（EX1 → 外観目線視点① ／ ベトナム語）。ベトナム語は、よく使うキーワード（EX・IN・EXCB・INCB・EXM・INM・EXP・INP・VR・VIDEO）だけ用意してあり、それ以外は日本語だけ出ます。
- ベトナム語の文言は `sync/Code.gs` の `STAFF_INPUT_COLUMNS`・`STAFF_RULES_LINES`・`VIEW_VI` にまとめてあります。直したら貼り付け直して「0. かんたん初期設定」を押せば、見出し・注記・記入ルールに反映されます。
- **『会社マスタ』『視点マスタ』を変えたら、メニュー「エンジニア入力シートを整える」を押す** と、会社コード・視点のプルダウンと視点コード表に反映されます。

エンジニアへの共有：「工程図 エンジニア入力シート」を制作メンバーに **編集者** で共有します（「工程図連携」は共有しない）。

### 2-5. 工程図との接続テスト

1. メニュー **工程図連携 → 工程図との接続テスト** を押す。
2. 「接続OK」と出れば完了です。失敗した場合は次項の **秘密鍵を設定** を行います。

### 2-6. 秘密鍵の設定（接続テストが失敗したときだけ）

1. Firebase コンソール（https://console.firebase.google.com/ ）→ プロジェクト **koutei-zu** → 歯車 **プロジェクトの設定 → サービス アカウント**。
2. **新しい秘密鍵の生成** を押して JSON ファイルをダウンロードする。
3. 「工程図連携」のメニュー **工程図連携 → 秘密鍵を設定** を押し、ダウンロードした JSON ファイルの中身をそのまま貼り付けて **保存**。
4. もう一度「接続テスト」を押す。
5. ダウンロードした JSON ファイルは他人に渡さず、用が済んだら削除してください（**リポジトリには絶対に入れない**）。
   鍵はスクリプトの「スクリプトプロパティ」にだけ保存され、シートには書き込まれません。

### 2-7. 会社名の表記を合わせる・会社コードのプルダウン・案件マスタ

1. メニュー **工程図連携 → 工程図の会社名一覧を取り込む** を押す。『会社マスタ』の E 列に工程図に登録済みの会社名が出ます。
2. 『会社マスタ』B 列「工程図の会社名」を、この表記に合わせて直します（「要確認」と書いてある行は特に確認）。
3. 『会社マスタ』D 列「入力シートに出さない」：チェックした行の会社コードは、エンジニアの会社コードのプルダウンに出ません。表記ゆれの行（備考に「表記ゆれ」とある行）には初期設定で自動でチェックが入ります。
   **新しい会社を足したら、メニュー「エンジニア入力シートを整える」を押す** と、プルダウンに反映されます。
4. 工程図の顧客マスタへの追加：『会社マスタ』B 列の会社のうち、工程図の顧客マスタ（マスタ → お客様設定）に無い会社は、「0. かんたん初期設定」、メニュー「会社マスタの会社を工程図の顧客マスタに追加」、自動登録の直前 に自動で追加されます（契約形態はラボ・売上区分は国内。変える場合は工程図のマスタで）。
   「株式会社サンゲツ」と「サンゲツ」のように **表記だけ違う会社は、二重に作らないよう追加しません**。結果に「△ … → 工程図では『…』」と出るので、『会社マスタ』B 列を工程図の表記に合わせてください。
5. 『案件マスタ』に、社内案件名（RIC.34）→ 社外案件名・会社名・お客様担当者 を登録します。ここに登録した案件は転記時に「要確認」になりにくくなります。
   社外案件名はエンジニアが入力シートに書くので、案件マスタは主に お客様担当者 と、会社コードだけでは決まらない会社名の登録に使います。

### 2-8. 『設定』タブ

| 項目 | 意味 |
|---|---|
| スタッフシートのファイルID | 「工程図 エンジニア入力シート」の URL の `/d/` と `/edit` の間の文字列（既定 `1BjPKtiHLsYuWcyKLg8FzB4zhmhq5Y5kI8Z2JOXVJuyo`） |
| スタッフシートのタブ名 | `入力シート`（9/21 版の『product schedule』、旧レイアウトの『案件シート(一覧)』も読めます） |
| 取込開始行 | この行より上は取り込まない。『入力シート』は 2（見出し行は自動で探すので、上に案内や書き方が入っていても問題ありません）。旧レイアウトを読むときは 4800 など |
| 既定の担当者 | 『連携』の担当者が空のときに使う名前（初期値「未割当」。工程図で後から変更できます） |
| FirebaseプロジェクトID・ワークスペースID | 通常は変更不要 |
| 自動登録 | 「する」（初期値）：30分ごとの自動実行で「未送信」の行と「工程図へ」にチェックした行を登録。「しない」：転記だけ自動（登録は「2. 工程図へ送信」で） |
| 自動登録の待ち時間（分） | 「未送信」の行は、最後に内容が変わってからこの分数（初期値 25）がたってから自動登録。エンジニアが入力ミスを直す時間 |
| 最後の自動実行 | 30分ごとの自動実行が最後に動いた日時と結果（自動で書き込み。エラーもここに出る） |

## 3. 毎日の使い方

### 自動で動くこと（30分ごと）

1. 入力シートに新しい行・変わった行があれば『連携』タブに反映します（変わりが無ければ何も書きません）。
   新しい行の **「入力日」に転記した日** が入ります（あとで変わりません。内容が変わった日時は「転記日時」）。
   記入途中の行（案件番号・新規or修正・時間が空）は取り込まずに待ちます。
2. 状態が **「未送信」**（自動判定がすべてできた行）で、最後に変わってから **25分** たった行を工程図に自動登録します。
   「工程図へ」にチェックが入った行（人が確認済み）も登録します。登録が済むと状態は「登録済み」、「工程図へ」のチェックは外れ、「結果」は「自動登録：新規○件…」になります。
3. 『設定』の「最後の自動実行」に日時と結果を書きます。止めたいときはメニュー **自動実行を止める**（再開は **自動実行を始める**）。すぐ動かしたいときは **自動実行（30分ごと）を今すぐ1回動かす**。

### 管理者がすること

1. 状態が **「要確認」** の行：「結果」列の理由を見て、社外案件名・会社名・区分・種類・ステップ種類 を直し、**「工程図へ」にチェック** → 次の自動実行で登録されます（すぐ登録したいときはメニュー **2. 工程図へ送信**）。二重入力なら「対象外」にチェック。
2. 状態が **「更新あり」** の行（登録後にエンジニアが時間などを直した）：内容を見て **「工程図へ」にチェック** → 工程図の未完了ステップの時間などを更新します（自動では更新しません。行の消し方によって別の行の中身がずれることがあるため）。
3. 状態が **「エラー」** の行：理由を直して「工程図へ」にチェックし、メニュー **2. 工程図へ送信**（エラーの行は自動では送り直しません）。
4. 必要に応じて 納期・お客様担当者・担当者（社内担当者）・メモ を入れます。**登録前に入れたものが工程図に入る** ので、「未送信」の行に入れたいものがあるときは、転記から25分以内に入れるか、『設定』の待ち時間を長くしてください。
5. 金額（売上・見積・請求）は工程図の請求パネルで入力します。

### 状態の意味

| 状態 | 意味 | 次にすること |
|---|---|---|
| 未送信 | 自動判定が全部できた。自動登録を待っている | 何もしなくてよい（25分後の自動実行で登録）。登録したくない行は「対象外」に |
| 要確認 | 社外案件名・会社名・種類のどれかが決まっていない、2回目以降なのに「新規」、入力シートから一度消えてまた出てきた | 直してから「工程図へ」にチェック（二重入力なら「対象外」） |
| 更新あり | 登録後にエンジニア側の時間・社外案件名・新規or修正などが変わった | 内容を見て「工程図へ」にチェックすると、未完了ステップの時間と案件名・会社名・区分・納期・社外視点名だけ更新 |
| 登録済み | 工程図に入っている | 何もしなくてよい（送り直したいときは状態を「更新あり」にして「工程図へ」にチェック） |
| エラー | 送信時に不備があった | 「結果」列の理由を直し、「工程図へ」にチェックして「2. 工程図へ送信」 |
| 元シートから消えた | 入力シートで行が消えた・書き換えられた（視点・パターンなどが変わると別の行になる）／旧レイアウトで完了チェックが付いた。**登録済みの行が消えた場合、工程図のタスクは残る**（「結果」に書く） | 登録済みだった行は、不要なら工程図側でタスクを削除 |

### 列の見方（『連携』タブ）

- **自動で入る列**: 取込キー・状態・入力日（最初に転記した日）・社内案件名・視点名・パターン・回・新規or修正・ホワイト時間・カラー時間・その他時間・元シート備考（メモ）・転記日時・送信日時・結果・元シート行・サーバリンク
- **人が直す列**: 工程図へ・社外案件名・社外視点名・納期・会社名・お客様担当者・区分・種類・ステップ種類・担当者・メモ・対象外
  （社外案件名・社外視点名・会社名・お客様担当者・区分・種類・ステップ種類は自動判定の結果が入り、人が直します。次の転記で上書きされません。ただし入力シートの社外案件名が書き換わったときは追従します）
- 納期・制作項目は今の入力シートに無いので、『連携』に人が入れた値がそのまま残ります（旧レイアウトを読むときだけ自動で入ります）。
- 列の順番は入れ替えても構いません（**見出しの文字は変えない**でください。見出しで列を探しています）。
  旧バージョンの見出し（カット名・White時間・Color時間）もそのまま使えます。「初期設定」で足りない列が右端に追加されます。

## 4. 自動判定のしくみ

| 判定 | 方法 |
|---|---|
| 社内案件名 | 会社コード＋「.」＋案件番号（`RIC` と `34` → `RIC.34`）。会社コードの欄に `RIC.34` と番号まで書いてあればそのまま |
| 社外案件名・お客様担当者 | 入力シートの社外案件名を優先。空なら『案件マスタ』を社内案件名で引く（お客様担当者は案件マスタから） |
| 会社名 | 『案件マスタ』の会社名 → 無ければ会社コード（例 `RIC`、旧レイアウトは `RENOBERU.58` → `RENOBERU`）を『会社マスタ』で引く → 無ければサーバリンクのフォルダ名から推定して「要確認」 |
| 区分・種類 | 視点の英字（例 `EX1` → `EX`、`EXCB1` → `EXCB`、`EXM1` → `EXM`、`HOTEL_IN1(D)` → `IN`）を『視点マスタ』で引く（英字部分がまるごと一致する行）。制作項目に「写真」「合成」があれば写真合成（旧レイアウト） |
| 社外視点名 | 『視点マスタ』の社外名（空なら区分＋「視点」、モデルは区分のまま）＋視点の番号の丸数字＋パターン。`EX1` → `外観目線視点①`、`EXCB2` → `外観鳥瞰視点②`、`EXM1` → `外観モデル①`、`IN2`＋パターンA → `内観目線視点②_パターンA`。番号が無ければ丸数字なし |
| ステップ種類 | 入力シートの「新規or修正」（新規 → 新規、修正 → 修正（無料））。有料の変更・追加は人がプルダウンで「変更（有料）」「追加」に直す。同じ案件＋視点の2回目以降なのに「新規」の行は「要確認」。旧レイアウトは制作項目（変更・修正・追加）と回数で判定 |
| 取込キー | `案件コード::視点名（パターン込み）::n回目`（例 `RIC34::EX1-A::2`）。案件コードは大文字にして点・空白を除いてから比べるので、`Ric.34` と `RIC 34` は同じ案件になります。記入途中の行も回数には数えるので、そろった後も同じキーになります |

- 区分は工程図の視点の「区分」（売上の制作種類）にそのまま入ります。工程図側でも外観・内観以外の区分を選べるようにしてあります。

## 5. 自動実行（30分ごと）のしくみ

- 「0. かんたん初期設定」で、関数 `autoRun` を30分ごとに動かすトリガーが1つ作られます（Apps Script の左の時計アイコンで確認できます。何度押しても1つだけ）。
- 1回の自動実行でやること：①転記（入力シートに変わりがあるときだけ書く）→ ②自動登録（対象の行があるときだけ工程図にアクセス）→ ③『設定』の「最後の自動実行」に結果を書く。
- 自動登録の対象：状態が「未送信」で、転記日時から25分たち、エンジニアが打ち直している最中でない行／「工程図へ」にチェックがあり、状態が 要確認・未送信・更新あり の行。エラー・登録済み・元シートから消えた・対象外の行は送りません。
- 手で押した転記・送信と自動実行が重なったときは、あとから来た方が待つか見送ります（二重登録しない）。
- 自動実行でエラーが起きると、『設定』の「最後の自動実行」にエラーの内容が出ます（Google からトリガーの失敗メールが届くこともあります）。
- 止める：メニュー「自動実行を止める」。再開：「自動実行を始める」。自動登録だけ止める：『設定』の「自動登録」を「しない」。

## 6. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「エンジニア入力シートにタブ「…」が見つかりません」 | 『設定』のタブ名が違う。「0. かんたん初期設定」を押すか、タブ名を直す |
| 「エンジニア入力シートの見出しが見つかりません」 | 見出し行の文字（会社コード・視点・White）が変わった。「0. かんたん初期設定」を押すと見出しを書き直します |
| 会社コードのプルダウンに新しい会社が出ない | 『会社マスタ』に足した後、メニュー「エンジニア入力シートを整える」を押す（「入力シートに出さない」にチェックが入っていないかも確認） |
| 転記の完了メッセージに「記入途中で待っている行」がある | 案件番号・新規or修正・時間（White / Color / pts）のどれかが空。エンジニアに書いてもらえば次の転記で追加されます |
| 「『連携』タブの見出しが見つかりません」 | 見出しの文字を変えてしまった。メニュー「初期設定」を押すと足りない見出しを右端に足します |
| 「送信対象がありません」 | 「工程図へ」にチェックが入っていない、または状態が「登録済み」。送り直すなら状態を「更新あり」にしてチェック |
| 自動で登録されない | 状態が「要確認」「更新あり」「エラー」（人の確認が必要）、転記から25分たっていない、エンジニアが打ち直し中、『設定』の自動登録が「しない」のどれか。『設定』の「最後の自動実行」も確認 |
| 自動実行が動いていない | 『設定』の「最後の自動実行」の日時が古い → メニュー「自動実行を始める」を押す（Apps Script の時計アイコンにトリガー `autoRun` があるか確認） |
| 視点のプルダウンに新しい視点が出ない | 『視点マスタ』に足した後、メニュー「エンジニア入力シートを整える」を押す |
| 結果に「△ … → 工程図では『…』」 | 『会社マスタ』の会社名と工程図の顧客マスタの表記が少し違う。二重登録を避けて追加していないので、『会社マスタ』B 列を工程図の表記に合わせる |
| 結果に「顧客マスタに未登録」 | 会社名の表記が工程図と違う。「会社名一覧を取り込む」で表記を確認して『会社マスタ』『案件マスタ』を直す（登録自体は済んでいるので、工程図側で会社名を直してもよい） |
| 接続テストが失敗 | 2-6 の秘密鍵を設定する。それでも失敗するなら、実行しているアカウントが Firebase プロジェクトのオーナーか確認 |
| 転記したはずの行が無い | 記入途中（上の行）か、『設定』の「取込開始行」より上の行です。見出し行より上の案内・書き方は読み飛ばされます |
| 同じ視点なのに別の視点として登録された | パターンの有無や視点の表記（EX1 と EX-1 など）が違う。入力シート側の表記をそろえる（視点はプルダウンから選ぶ） |

## 7. 注意事項

- 工程図に送った内容は、工程図のメンバー全員が見られます。見せたくない情報は『連携』シートに留めてください（送るのは案件名・会社名・お客様担当者・視点名・社外視点名・区分・納期・担当者・時間・メモだけです）。
- 旧スクリプト（スタッフシート側に置いて匿名ログインで書き込む方式）は、メンバー制限の導入とタスク保存方式の変更で動かなくなったため廃止しました。スタッフシート側の Apps Script に残っていれば削除して構いません。
- 開発者向け：純ロジック（判定・レコード生成・自動登録の対象・顧客マスタへの追加）は `node sync/test/logic.test.mjs`、シート操作（かんたん初期設定・入力シートの整備・転記・30分ごとの自動実行）は偽のシート環境と偽の Firestore で `node sync/test/setup.test.mjs` で確認できます。
