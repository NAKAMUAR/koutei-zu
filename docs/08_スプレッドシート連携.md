## 1. 全体の流れ

```
エンジニアが書く「工程図 エンジニア入力シート」の『product schedule』タブ（制作メンバーに共有）
   社内案件名 / 視点名（EX1・IN1）/ パターン（A・B）/ ホワイト時間 / カラー時間 / その他時間
        │  ① 転記（ボタン1つ。新しい行だけ追加。人が直した欄は上書きしない）
        ▼
「工程図連携」シート（管理者だけが見られる・別ファイル）
   ・案件マスタ：社内案件名 → 社外案件名・会社名・お客様担当者
   ・視点マスタ：EX → 外観・パース・「外観視点」、IN → 内観・パース・「内観視点」
   ・EX1 → 社外視点名「外観視点①」、パターンA → 「外観視点①_パターンA」
   ・「要確認」の行だけ人が直し、社内担当者などを入れて「工程図へ」にチェック
        │  ② 送信（ボタン1つ。チェック済みの行だけ）
        ▼
工程図（koutei-zu）
   ・ホワイト時間 → 「ホワイト」、カラー時間 → 「カラー」、その他時間 → 「人物＋添景合成」のステップ
   ・同じ案件＋視点の2回目以降 → 「修正」ステップとして同じ視点に追加
   ・種類（新規／追加／修正）は売上・帳票の「初回／追加／修正」として登録
        │
        ▼  工程図の既存機能
   スケジュールの自動反映 → 売上表の登録・集計 → 見積書・発注書・請求書の作成
   （金額は工程図の請求パネルで入力。顧客マスタに単価が無いため自動計算はしない）
```

工程図に登録したあとの担当者・優先度・完了時間・完了状態は工程図側が正で、シートからは上書きしません。
工程図側で削除したタスクは、再送信しても復活しません。

## 2. 最初に1回だけ行うこと

### 2-1. シートの置き場所と共有

- 「工程図連携」は **一般スタッフには共有しない** でください（会社名などの紐づけ情報を含みます）。
- 「工程図 エンジニア入力シート」は、制作メンバー（エンジニア）に **編集** 権限で共有してください。
- スクリプトを動かす Google アカウント（kei.n412）に、次の2つの権限が必要です。
  1. 「工程図連携」の **編集** 権限
  2. 「工程図 エンジニア入力シート」の **編集** 権限（読み取りだけでも転記はできますが、タブ作成には編集が必要）
- kei.n412 は工程図の Firebase プロジェクトのオーナーなので、**Firebase 側の追加登録は不要** です。

### 2-2. スクリプトの貼り付け

1. 「工程図連携」を開き、メニュー **拡張機能 → Apps Script** を開く。
2. 左の「コード.gs」の中身を全部消して、リポジトリの `sync/Code.gs` の内容を貼り付ける。
3. 左の歯車（プロジェクトの設定）→ **「appsscript.json」マニフェスト ファイルをエディタで表示** にチェック。
   エディタに戻ると `appsscript.json` が見えるので、中身を `sync/appsscript.json` の内容に置き換える。
4. 保存（フロッピーのアイコン）。
5. シートに戻って **再読み込み** すると、上のメニューに **「工程図連携」** が出ます。

### 2-3. 初期設定と権限の承認

1. メニュー **工程図連携 → 初期設定（タブ・チェックボックスを整える）** を押す。
2. 初回は「承認が必要です」と出るので、**権限を確認 → アカウントを選択**。
   「このアプリは Google で確認されていません」と出たら **詳細 → （安全ではないページ）に移動** を押して進めます（自作のスクリプトなので問題ありません）。
3. もう一度「初期設定」を押すと、『連携』の新しい列・『案件マスタ』タブ・チェックボックス・プルダウン・『使い方』が整います。
   『会社マスタ』『視点マスタ』が空のときは初期値も入ります（すでに入っていれば触りません。『視点マスタ』に「社外名」列が無ければ足します）。

### 2-4. エンジニア入力タブを整える

「工程図 エンジニア入力シート」は作成済みで、1枚目のタブに **書き方・記入例・見出し行** が入っています。そのまま使えますが、チェックボックスやプルダウンも付けたい場合は次を行います。

1. 『設定』タブの **スタッフシートのファイルID** が `1BjPKtiHLsYuWcyKLg8FzB4zhmhq5Y5kI8Z2JOXVJuyo` になっていることを確認する。
2. メニュー **工程図連携 → スタッフ入力タブ（product schedule）を作成** を押す。
   書式・注記・プルダウン付きの『product schedule』タブが追加され、『設定』のタブ名と取込開始行が自動で合います。
3. 最初からあるタブは「書き方・記入例」などに名前を変えて、案内用に残しておくと便利です。
   （手順2を行わない場合は、最初のタブの名前を `product schedule` に変えるだけでも動きます）
4. エンジニアには「今後はこのタブに1カット1行で書く」と案内してください。列は次のとおりです。

| 列 | 書き方 |
|---|---|
| 入力日 | 例 9/18（任意） |
| 社内案件名 | 案件名＋番号（例 RIC.34）。大文字小文字・点・空白の違いは無視して照合します |
| 視点名 | 外観1 → EX1、内観1 → IN1 |
| パターン | A / B / C（無ければ空）。「Aパターン」「パターンA」と書いても A として読みます |
| ホワイト時間 | 躯体・家具・レンダリング・照明・カメラ設定（時間） |
| カラー時間 | 色付け・レンダリング（時間） |
| その他時間 | 人物・点景・色分など（時間） |
| 納期 | 例 9/30（任意） |
| 備考 | 任意（『連携』の「元シート備考」に写ります） |
| 完了 | 作業完了／作成無しならチェック（チェックした行は取り込まない） |

新規・追加・修正を問わず同じタブに書きます。同じ社内案件名＋視点名（パターン込み）が2回目以降なら、自動で「修正」扱いになります。

### 2-5. 工程図との接続テスト

1. メニュー **工程図連携 → 工程図との接続テスト** を押す。
2. 「接続OK」と出れば完了です。失敗した場合は次項の **秘密鍵を設定** を行います。

### 2-6. 秘密鍵の設定（接続テストが失敗したときだけ）

1. Firebase コンソール（https://console.firebase.google.com/ ）→ プロジェクト **koutei-zu** → 歯車 **プロジェクトの設定 → サービス アカウント**。
2. **新しい秘密鍵の生成** を押して JSON ファイルをダウンロードする。
3. 「工程図連携」のメニュー **工程図連携 → 秘密鍵を設定** を押し、ダウンロードした JSON ファイルの中身をそのまま貼り付けて **保存**。
4. もう一度「接続テスト」を押す。
5. ダウンロードした JSON ファイルは他人に渡さず、用が済んだら削除してください（**リポジトリには絶対に入れない**）。
   鍵はスクリプトの「スクリプトプロパティ」にだけ保存され、シートには書き込まれません。

### 2-7. 会社名の表記を合わせる・案件マスタを作る

1. メニュー **工程図連携 → 工程図の会社名一覧を取り込む** を押す。『会社マスタ』の E 列に工程図に登録済みの会社名が出ます。
2. 『会社マスタ』B 列「工程図の会社名」を、この表記に合わせて直します（「要確認」と書いてある行は特に確認）。
3. 『案件マスタ』に、社内案件名 → 社外案件名・会社名・お客様担当者 を登録します。ここに登録した案件は転記時に「要確認」になりません。
   案件マスタに無い案件は、転記後に『連携』の「社外案件名」を人が入れます（空のまま送ると社内案件名で登録されます）。

### 2-8. 『設定』タブ

| 項目 | 意味 |
|---|---|
| スタッフシートのファイルID | 「工程図 エンジニア入力シート」の URL の `/d/` と `/edit` の間の文字列（既定 `1BjPKtiHLsYuWcyKLg8FzB4zhmhq5Y5kI8Z2JOXVJuyo`） |
| スタッフシートのタブ名 | `product schedule`（旧レイアウトの『案件シート(一覧)』も読めます） |
| 取込開始行 | この行より上は取り込まない。『product schedule』は 2（見出し行は自動で探すので、上に書き方が入っていても問題ありません）。旧レイアウトを読むときは 4800 など |
| 既定の担当者 | 『連携』の担当者が空のときに使う名前（初期値「未割当」。工程図で後から変更できます） |
| FirebaseプロジェクトID・ワークスペースID | 通常は変更不要 |

## 3. 毎日の使い方（管理者）

1. **工程図連携 → 1. スタッフシートから転記**
   『連携』タブに新しい行が追加されます。
2. 状態が **「要確認」** の行の 社外案件名・会社名・区分・種類 を直す（「結果」列に理由が書いてあります）。
   必要なら お客様担当者・担当者（社内担当者）・メモ も入れます。工程図に入れない行は「対象外」にチェック。
3. 工程図に登録したい行の **「工程図へ」** にチェックを入れる。
4. **工程図連携 → 2. 工程図へ送信**
   状態が **「登録済み」** になれば完了です。「結果」列に登録件数が入ります。
   送る前に中身を見たいときは **送信内容のプレビュー** を使います（何も書き込みません）。
5. 工程図側でスケジュールが自動生成されます。金額（売上・見積・請求）は工程図の請求パネルで入力します。

### 状態の意味

| 状態 | 意味 | 次にすること |
|---|---|---|
| 未送信 | 自動判定が全部できた。まだ送っていない | 内容を見て「工程図へ」にチェック |
| 要確認 | 社外案件名・会社名・種類のどれかが決まっていない | 直してから「工程図へ」にチェック |
| 更新あり | 登録後にスタッフシート側の時間や視点名が変わった | もう一度送信すると、未完了ステップの時間と案件名・会社名・区分・納期・社外視点名だけ更新 |
| 登録済み | 工程図に入っている | 何もしなくてよい（送り直したいときは状態を「更新あり」に変える） |
| エラー | 送信時に不備があった | 「結果」列の理由を直して再送信 |
| 元シートから消えた | スタッフシートで完了チェックが付いた／行が消えた／取込開始行より上になった | 送っていない行なので、必要なら「対象外」に |

### 列の見方（『連携』タブ）

- **自動で入る列**: 取込キー・状態・社内案件名・視点名・パターン・回・納期・ホワイト時間・カラー時間・その他時間・制作項目・元シート備考・転記日時・送信日時・結果・元シート行・サーバリンク
- **人が直す列**: 工程図へ・社外案件名・社外視点名・会社名・お客様担当者・区分・種類・ステップ種類・担当者・メモ・対象外
  （社外案件名・社外視点名・会社名・お客様担当者・区分・種類・ステップ種類は自動判定の結果が入り、人が直します。次の転記で上書きされません）
- 列の順番は入れ替えても構いません（**見出しの文字は変えない**でください。見出しで列を探しています）。
  旧バージョンの見出し（カット名・White時間・Color時間）もそのまま使えます。「初期設定」で足りない列が右端に追加されます。

## 4. 自動判定のしくみ

| 判定 | 方法 |
|---|---|
| 社外案件名・お客様担当者 | 『案件マスタ』を社内案件名で引く（スタッフシートに社外案件名の列があればそちらを優先） |
| 会社名 | 『案件マスタ』の会社名 → 無ければ社内案件名の英字部分（例 `RENOBERU.58` → `RENOBERU`）を『会社マスタ』で引く → 無ければサーバリンクのフォルダ名から推定して「要確認」 |
| 区分（外観/内観）・種類 | 視点名の英字（例 `EX1` → `EX`、`HOTEL_IN1(D)` → `IN`、`A-LDK2` → `LDK`）を『視点マスタ』で引く。先に書いた行が優先。制作項目に「写真」「合成」があれば写真合成 |
| 社外視点名 | 『視点マスタ』の社外名＋視点名の番号の丸数字＋パターン。`EX1` → `外観視点①`、`IN2`＋パターンA → `内観視点②_パターンA`。番号が無ければ丸数字なし |
| ステップ種類 | 制作項目に「変更」→ 変更（有料）、「修正」→ 修正（無料）、「追加」→ 追加、同じ案件＋視点の2回目以降 → 修正（無料）、それ以外 → 新規。人がプルダウンで変えられます |
| 取込キー | `案件コード::視点名（パターン込み）::n回目`（例 `RIC34::EX1-A::2`）。案件コードは大文字にして点・空白を除いてから比べるので、`Ric.34` と `RIC 34` は同じ案件になります |

工程図には次のように登録されます。

| 種類 | 登録されるステップ | 売上・帳票の納品種類 |
|---|---|---|
| パース・新規 | ホワイト時間 → 「ホワイト」、カラー時間 → 「カラー」、その他時間 → 「人物＋添景合成」 | 初回 |
| パース・追加 | 同上 | 追加 |
| パース・修正（無料） | 「ホワイト修正n回目（無料）」「カラー修正n回目（無料）」（その他は「人物＋添景合成」） | 修正 |
| パース・変更（有料） | 「ホワイト変更n回目（有料）」「カラー変更n回目（有料）」 | 修正 |
| 写真合成 | 「写真合成」1ステップ（時間はホワイト＋カラー＋その他の合計） | 種類に応じて同上 |

- 工程図の視点名（内部）は `EX1`、パターンがあれば `EX1-A`。社外視点名は `外観視点①_パターンA`。納品名は工程図の規則どおり「社外案件名_社外視点名_白色」などになります。
- 2回目以降は、同じ案件名・視点名の視点に **続きのステップとして追加** されます（担当者はその視点の担当者を引き継ぎます）。
- 金額は入れません（顧客マスタに単価が無いため）。工程図の請求パネルで金額を入れると売上表に反映され、見積書・発注書・請求書を作れます。

## 5. 転記を自動で動かす（任意）

転記だけは毎朝自動にできます（送信は人の確認が入るので手動のままを推奨）。

1. Apps Script の画面で左の **時計アイコン（トリガー）** → **トリガーを追加**。
2. 実行する関数 `transferFromStaffSheet`、イベントのソース **時間主導型**、**日付ベースのタイマー**、時刻（例 午前 8〜9 時）→ 保存。

## 6. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「スタッフシートにタブ「…」が見つかりません」 | 『設定』のタブ名が違う。メニュー「スタッフ入力タブを作成」を実行するか、タブ名を直す |
| 「スタッフシートの見出しが見つかりません」 | 見出し行の文字（社内案件名・視点名・ホワイト時間）が変わった。見出しを戻す |
| 「『連携』タブの見出しが見つかりません」 | 見出しの文字を変えてしまった。メニュー「初期設定」を押すと足りない見出しを右端に足します |
| 「送信対象がありません」 | 「工程図へ」にチェックが入っていない、または状態が「登録済み」。送り直すなら状態を「更新あり」に |
| 結果に「顧客マスタに未登録」 | 会社名の表記が工程図と違う。「会社名一覧を取り込む」で表記を確認して『会社マスタ』『案件マスタ』を直す（登録自体は済んでいるので、工程図側で会社名を直してもよい） |
| 接続テストが失敗 | 2-6 の秘密鍵を設定する。それでも失敗するなら、実行しているアカウントが Firebase プロジェクトのオーナーか確認 |
| 転記したはずの行が無い | 『設定』の「取込開始行」より上の行、または「完了」にチェックが付いた行は取り込みません。見出し行（社内案件名…）より上の書き方・記入例は読み飛ばされます |
| 同じ視点なのに別の視点として登録された | パターンの有無や視点名の表記（EX1 と EX-1 など）が違う。スタッフシート側の表記をそろえる |

## 7. 注意事項

- 工程図に送った内容は、工程図のメンバー全員が見られます。見せたくない情報は『連携』シートに留めてください（送るのは案件名・会社名・お客様担当者・視点名・社外視点名・区分・納期・担当者・時間・メモだけです）。
- 旧スクリプト（スタッフシート側に置いて匿名ログインで書き込む方式）は、メンバー制限の導入とタスク保存方式の変更で動かなくなったため廃止しました。スタッフシート側の Apps Script に残っていれば削除して構いません。
- 開発者向け：純ロジック（判定・レコード生成）は `node sync/test/logic.test.mjs` で確認できます。
