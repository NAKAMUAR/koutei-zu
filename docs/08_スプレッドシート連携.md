# スプレッドシート連携（スタッフシート → 工程図連携シート → 工程図）

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-09-18 |
| 対象 | スタッフが書く「Project Schedule」の内容を、人が確認・補正してから工程図（koutei-zu）に登録する仕組み |
| 使うもの | Google スプレッドシート「工程図連携」＋ その中に貼り付ける Apps Script（`sync/Code.gs`・`sync/appsscript.json`） |
| 連携シート | https://docs.google.com/spreadsheets/d/1xS9uRwSNVb9qRPyl1uO8Mib5OaNAHjY_DF8drngGpEo/edit |
| スタッフシート | 「Project Schedule」の『案件シート(一覧)』タブ（ファイルID `12IfXNtu67LNuqRnB6Iako0pvI1A3k1CzyQTS4F3u5fU`） |

## 1. 全体の流れ

```
スタッフが書く「Project Schedule」（全員が見られる）
        │  ① 転記（ボタン1つ。新しいカットだけ追加。人が直した欄は上書きしない）
        ▼
「工程図連携」シート（限られた人だけが見られる・別ファイル）
   ・会社名／区分（外観・内観）／種類（パース・写真合成）を自動判定
   ・「要確認」の行だけ人が直す → 「工程図へ」にチェック
        │  ② 送信（ボタン1つ。チェック済みの行だけ）
        ▼
工程図（koutei-zu）
   ・White時間 → 「ホワイト」ステップ、Color時間 → 「カラー」ステップ
   ・2回目以降の同じカット → 「修正（無料）」ステップとして同じ視点に追加
```

工程図に登録したあとの担当者・優先度・完了時間・完了状態は工程図側が正で、シートからは上書きしません。
工程図側で削除したタスクは、再送信しても復活しません。

## 2. 最初に1回だけ行うこと

### 2-1. シートの置き場所と共有

- 「工程図連携」は **一般スタッフには共有しない** でください（会社名などの紐づけ情報を含みます）。
  スタッフが見られる共有ドライブには置かず、マイドライブに置きます。
- スクリプトを動かす Google アカウント（kei.n412）に、次の2つの権限が必要です。
  1. 「工程図連携」の **編集** 権限
  2. 「Project Schedule」（スタッフシート）の **閲覧** 権限（同じ共有ドライブのメンバーなら通常あります）
- kei.n412 は工程図の Firebase プロジェクトのオーナーなので、**Firebase 側の追加登録は不要** です。

### 2-2. スクリプトの貼り付け

1. 「工程図連携」を開き、メニュー **拡張機能 → Apps Script** を開く。
2. 左の「コード.gs」の中身を全部消して、リポジトリの `sync/Code.gs` の内容を貼り付ける。
3. 左の歯車（プロジェクトの設定）→ **「appsscript.json」マニフェスト ファイルをエディタで表示** にチェック。
   エディタに戻ると `appsscript.json` が見えるので、中身を `sync/appsscript.json` の内容に置き換える。
4. 保存（フロッピーのアイコン）。
5. シートに戻って **再読み込み** すると、上のメニューに **「工程図連携」** が出ます。

### 2-3. 初期設定と権限の承認

1. メニュー **工程図連携 → 初期設定（タブ・チェックボックスを整える）** を押す。
2. 初回は「承認が必要です」と出るので、**権限を確認 → アカウントを選択**。
   「このアプリは Google で確認されていません」と出たら **詳細 → （安全ではないページ）に移動** を押して進めます（自作のスクリプトなので問題ありません）。
3. もう一度「初期設定」を押すと、チェックボックスやプルダウンが整います。
   『会社マスタ』『視点マスタ』が空のときは初期値も入ります（すでに入っていれば触りません）。

### 2-4. 工程図との接続テスト

1. メニュー **工程図連携 → 工程図との接続テスト** を押す。
2. 「接続OK」と出れば完了です。
3. 失敗した場合は **秘密鍵を設定** します（次項）。

### 2-5. 秘密鍵の設定（接続テストが失敗したときだけ）

1. Firebase コンソール（https://console.firebase.google.com/ ）→ プロジェクト **koutei-zu** → 歯車 **プロジェクトの設定 → サービス アカウント**。
2. **新しい秘密鍵の生成** を押して JSON ファイルをダウンロードする。
3. 「工程図連携」のメニュー **工程図連携 → 秘密鍵を設定** を押し、ダウンロードした JSON ファイルの中身をそのまま貼り付けて **保存**。
4. もう一度「接続テスト」を押す。
5. ダウンロードした JSON ファイルは他人に渡さず、用が済んだら削除してください（**リポジトリには絶対に入れない**）。
   鍵はスクリプトの「スクリプトプロパティ」にだけ保存され、シートには書き込まれません。

### 2-6. 会社名の表記を合わせる

1. メニュー **工程図連携 → 工程図の会社名一覧を取り込む** を押す。
2. 『会社マスタ』タブの E 列に、工程図に登録済みの会社名が出ます。
3. B 列「工程図の会社名」を、この表記に合わせて直します（「要確認」と書いてある行は特に確認）。
   表記が違うと、工程図では別の会社として扱われます。

### 2-7. 『設定』タブの確認

| 項目 | 意味 |
|---|---|
| スタッフシートのファイルID | 「Project Schedule」の URL の `/d/` と `/edit` の間の文字列 |
| スタッフシートのタブ名 | `案件シート(一覧)` |
| 取込開始行 | この行より上は取り込まない。最初は 4800（最近の行だけ）。古い行も対象にしたいときは小さくする |
| 既定の担当者 | 『連携』の担当者が空のときに使う名前（初期値「未割当」。工程図で後から変更できます） |
| FirebaseプロジェクトID・ワークスペースID | 通常は変更不要 |

## 3. 毎日の使い方

1. **工程図連携 → 1. スタッフシートから転記**
   『連携』タブに新しいカットが追加されます。
2. 状態が **「要確認」** の行の 会社名・区分・種類 を直す（「結果」列に理由が書いてあります）。
   必要なら 担当者・メモ も入れます。工程図に入れない行は「対象外」にチェック。
3. 工程図に登録したい行の **「工程図へ」** にチェックを入れる。
4. **工程図連携 → 2. 工程図へ送信**
   状態が **「登録済み」** になれば完了です。「結果」列に登録件数が入ります。
   送る前に中身を見たいときは **送信内容のプレビュー** を使います（何も書き込みません）。

### 状態の意味

| 状態 | 意味 | 次にすること |
|---|---|---|
| 未送信 | 自動判定が全部できた。まだ送っていない | 内容を見て「工程図へ」にチェック |
| 要確認 | 会社名か種類が決まっていない | 直してから「工程図へ」にチェック |
| 更新あり | 登録後にスタッフシート側の時間や案件名が変わった | もう一度送信すると、未完了ステップの時間と案件名・会社名・区分・納期だけ更新 |
| 登録済み | 工程図に入っている | 何もしなくてよい（送り直したいときは状態を「更新あり」に変える） |
| エラー | 送信時に不備があった | 「結果」列の理由を直して再送信 |
| 元シートから消えた | スタッフシートで完了チェックが付いた／行が消えた／取込開始行より上になった | 送っていない行なので、必要なら「対象外」に |

### 列の見方（『連携』タブ）

- **灰色の列**（取込キー・状態・社内案件名・社外案件名・カット名・回・納期・White時間・Color時間・制作項目・転記日時・送信日時・結果・元シート行・サーバリンク）は自動で入る列です。
- **黄色の列**（工程図へ・会社名・区分・種類・ステップ種類・担当者・メモ・対象外）は人が触る列です。
  会社名・区分・種類・ステップ種類は自動判定の結果が入り、人が直します。次の転記で上書きされることはありません。
- 列の順番は入れ替えても構いません（**見出しの文字は変えない**でください。見出しで列を探しています）。

## 4. 自動判定のしくみ

| 判定 | 方法 |
|---|---|
| 会社名 | 社内案件名の英字部分（例 `RENOBERU.58` → `RENOBERU`、`REN84` → `REN`）を『会社マスタ』A 列で引く。無ければサーバリンクのフォルダ名（例「株式会社リックデザイン(RIC)」）から推定して「要確認」にする |
| 区分（外観/内観） | カット名の英字（例 `EX1` → `EX`、`HOTEL_IN1(D)` → `IN`、`A-LDK2` → `LDK`）を『視点マスタ』A 列で引く。先に書いた行が優先 |
| 種類（パース/写真合成） | 制作項目に「写真」「合成」があれば写真合成、「パース」があればパース。無ければ『視点マスタ』C 列 |
| ステップ種類 | 制作項目に「変更」→ 変更（有料）、「修正」→ 修正（無料）、同じ案件＋カットの2回目以降 → 修正（無料）、それ以外 → 新規 |
| 取込キー | `案件コード::カット名::n回目`（例 `RIC34::EX1::2`）。案件コードは大文字にして点・空白を除いてから比べるので、`Ric.34` と `RIC 34` は同じ案件になります |

工程図には次のように登録されます。

| 種類 | 登録されるステップ |
|---|---|
| パース・新規 | White時間 > 0 なら「ホワイト」、Color時間 > 0 なら「カラー」 |
| パース・修正（無料） | 「ホワイト修正n回目（無料）」「カラー修正n回目（無料）」 |
| パース・変更（有料） | 「ホワイト変更n回目（有料）」「カラー変更n回目（有料）」 |
| 写真合成 | 「写真合成」1ステップ（時間は White＋Color の合計） |

2回目以降は、同じ案件名・カット名の視点に **続きのステップとして追加** されます（担当者はその視点の担当者を引き継ぎます）。

## 5. 転記を自動で動かす（任意）

転記だけは毎朝自動にできます（送信は人の確認が入るので手動のままを推奨）。

1. Apps Script の画面で左の **時計アイコン（トリガー）** → **トリガーを追加**。
2. 実行する関数 `transferFromStaffSheet`、イベントのソース **時間主導型**、**日付ベースのタイマー**、時刻（例 午前 8〜9 時）→ 保存。

## 6. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「スタッフシートの見出しが見つかりません」 | 『設定』のタブ名が違う、または見出し行の文字（社内案件名・カット名・予想時間）が変わった。タブ名を確認 |
| 「『連携』タブの見出しが見つかりません」 | 見出しの文字を変えてしまった。メニュー「初期設定」を押すと足りない見出しを右端に足します |
| 「送信対象がありません」 | 「工程図へ」にチェックが入っていない、または状態が「登録済み」。送り直すなら状態を「更新あり」に |
| 結果に「顧客マスタに未登録」 | 会社名の表記が工程図と違う。「会社名一覧を取り込む」で表記を確認して『会社マスタ』を直す（登録自体は済んでいるので、工程図側で会社名を直してもよい） |
| 接続テストが失敗 | 2-5 の秘密鍵を設定する。それでも失敗するなら、実行しているアカウントが Firebase プロジェクトのオーナーか確認 |
| 転記したはずの行が無い | 『設定』の「取込開始行」より上の行、または「作業完了/作成無し」にチェックが付いた行は取り込みません |

## 7. 注意事項

- 工程図に送った内容は、工程図のメンバー全員が見られます。見せたくない情報は『連携』シートに留めてください（送るのは案件名・会社名・カット名・区分・納期・担当者・時間・メモだけです）。
- 旧スクリプト（スタッフシート側に置いて匿名ログインで書き込む方式）は、メンバー制限の導入とタスク保存方式の変更で動かなくなったため廃止しました。スタッフシート側の Apps Script に残っていれば削除して構いません。
- 開発者向け：純ロジック（判定・レコード生成）は `node sync/test/logic.test.mjs` で確認できます。
