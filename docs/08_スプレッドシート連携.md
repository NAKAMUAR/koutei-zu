> **『案件入力』タブ（縦型フォーム、2026-11-04）**：管理者用シートの先頭のタブ。A列が項目名、B列から入力、V列は隠し列（視点コード）。上から 会社コード・案件番号・社外案件名・お客様担当者・新規or修正（案件で1つ）・サーバーリンク・納期・注文書・管理者メモ・前回の視点を呼び出す → ①視点を選ぶ（区分の日本語＝外観目線・内観目線…の行に番号1〜20のチェックボックス）→ 登録する視点（2F 外観目線②・外観目線①-A…（n件））→ 登録 → 結果 → ②視点（1行ずつ：視点の日本語・部屋名・パターン・＋・外す・社外視点名）。①にチェックすると②に1行でき、外すと消える（残った視点の行の直した内容は保つ）。＋にチェックでその視点（同じ部屋）にパターンを足す（なし→A・B、あれば次の文字）。外すにチェックでその行を消す。部屋名を書くと社外視点名の頭に付き（2F外観目線視点②）、工程図・入力シートの視点は「コード_部屋名」（EXE2_2F）。「2F,3F」と書くと部屋ごとの行に分かれる。社外視点名は『視点マスタ』から自動で、お客様の呼び方が違うときだけ書き換える（書き換えた名前は部屋名・パターンを変えても残る）。「前回の視点を呼び出す」は同じ会社コード・案件番号の『登録一覧』でいちばん新しい登録日の視点（部屋名・パターン・社外視点名も）を入れ、新規or修正を「修正」にする。会社コードと案件番号を入れたとき、過去に登録した案件なら空の社外案件名・お客様担当者を自動で入れる（『登録一覧』のいちばん新しい登録 → 無ければ『連携』の下の行から。入っている欄は上書きしない。`formFillKnown_`・`formKnownProject_`、2026-11-05）。「登録」にチェックすると、足りなければ結果に ✗、そろっていれば確認の画面（登録する視点の一覧と通訳へのメッセージ）が出て、「登録する」で `submitFormSheet` → `submitEntryForm`（『登録一覧』に視点ごとの行・登録No・入力シートへ写す）。フォームは空に戻る。確認の画面には『設定』の「通訳向けの連絡文」から作った連絡文が出て、書いたメッセージは最後に足される。登録すると『登録一覧』に入った連絡文を選んだ状態にしてコピーを試みる（できなければ ⌘C）。動きは `onAdminEdit` → `onFormEdit_`。行の場所はA列の文字とV列のコードで探す（`formMap_`）。視点マスタを変えたらメニュー「『案件入力』タブを作り直す」。
> 『登録一覧』に「社外視点名」列（パターンの右）を足した。前の版のシートでは初期設定・登録のときに差し込む。ここに書いた名前は、転記のとき『連携』の社外視点名に入る（空なら従来どおり自動）。
> **入力画面（縦型）**：メニュー「工程図連携 → 案件を登録（入力画面）」で、項目が縦に並んだ入力画面が開く（会社コード・案件番号・社外案件名・お客様担当者・サーバーリンク・納期・注文書・管理者メモ・通訳へのメッセージ・新規or修正）。1案件ぶんの視点は、EX・IN などの種類ごとに並んだ番号ボタンを押してまとめて選び、選んだ視点ごとにパターン（なし・A・B…、複数可）を押す。下に「登録する視点：EX1-A・EX1-B・EX2（3件）」と出る。新規or修正は案件で1つ。「この案件を登録」で視点ごとに『登録一覧』へ書き、その場で登録No を付けて入力シートへ写す。足りない項目・同じ視点の重複はその場で知らせて書かない（`entryFormRows_`・`submitEntryForm`・`entryFormHtml_`）。
> あわせて、自動実行を **15分ごと**、自動登録の待ち時間を **15分**（『設定』で変更可）にした。工程図に登録した後でエンジニア入力シートの内容が変わった行は、これまでどおり「更新あり」にして自動では書き換えず、**Discord で確認を頼む**（変わった項目と前後の値を書く。同じ変更では1回だけ）。

## 1. 全体の流れ

```
「工程図 エンジニア入力シート」（制作メンバーに共有）
   『入力シート』タブ：1視点1行
     会社コード（REN・RIC…）/ 案件番号 / 社外案件名 / サーバーリンク / 新規or修正 /
     視点（EX1・IN1・EXCB1・INCB1・EXM1・INM1・EXP1・INP1・VR1・VIDEO1…）/ パターン（A・B…）/ White / Color / pts / メモ
   『記入ルール/説明』タブ：書き方（日本語・ベトナム語）
        │  ① 30分ごとに自動で転記（変わりがあれば、その分だけ。記入途中の行は待つ。人が直した欄は上書きしない）
        ▼
「工程図連携」シート（管理者だけが見られる・別ファイル。エンジニアには共有しない）
   ・入力日：最初に転記した日を自動で記録
   ・会社コード＋案件番号 → 社内案件名「RIC.34」
   ・会社マスタ：RIC → 株式会社リックデザイン（エンジニアの会社コードのプルダウンもここから作る）
   ・案件マスタ：RIC.34 → 社外案件名・会社名・お客様担当者
   ・視点マスタ：EX → 区分「外観目線」・種類「パース」、EXM → 「外観モデル」「モデル」、VR → 種類「VR」（視点のプルダウンもここから作る）
   ・EX1 → 社外視点名「外観目線視点①」（区分＋視点＋丸数字）、パターンA → 「外観目線視点①_パターンA」
   ・自動判定がすべてできた行は「未送信」、足りない行は「要確認」
        │  ② 同じ30分ごとの自動実行で、「未送信」の行を自動登録（転記から25分待つ＝入力ミスを直す時間）
        │     「要確認」「更新あり」の行は、人が直して「工程図へ」にチェック → 次の自動実行で登録
        ▼
工程図（koutei-zu）
   ・White → 「ホワイト」、Color → 「カラー」、pts → 「人物＋添景合成」のステップ
   ・パース以外は1ステップ（写真合成 → 「写真合成」、モデル → 「モデル作成」、VR → 「VR制作」、動画 → 「動画制作」。時間は合計）
   ・「修正」の行 → 「修正」ステップとして同じ視点に追加
   ・種類（新規／追加／修正）は売上・帳票の「初回／追加／修正」として登録
   ・『会社マスタ』の会社が顧客マスタに無ければ、先に顧客マスタへ追加
        │
        ▼  工程図の既存機能
   スケジュールの自動反映 → 売上表の登録・集計 → 見積書・発注書・請求書の作成
   （金額は工程図の請求パネルで入力。顧客マスタに単価が無いため自動計算はしない）
```

工程図に登録したあとの担当者・優先度・完了時間・完了状態は工程図側が正で、シートからは上書きしません。
工程図側で削除したタスクは、再送信しても復活しません。

### 1-2. 案件登録の流れ（管理者 → 通訳 → エンジニア）

```
① 管理者：連携シートの『案件登録』タブに1視点1行で書く（黄色い見出しの列）
     会社コード / 案件番号 / 社外案件名 / お客様担当者 / 新規or修正 / 視点 / パターン / サーバーリンク / 納期 / 注文書 / 管理者メモ
     → 「入力日」は書き始めた日が自動で入る。会社コード・案件番号・視点・新規or修正がそろうと「登録No」（R0001…）が付く
        │  30分ごとの自動実行（すぐなら メニュー「案件登録を入力シートへ写す」）
        ▼
② エンジニア入力シートに 会社コード・案件番号・社外案件名・サーバーリンク・新規or修正・視点・パターン・登録No を写す
     （お客様担当者・納期・注文書・管理者メモは写さない。『案件登録』で直すと入力シートの行も直る）
        ▼
1.5 通訳：「翻訳済み」にチェック（訳は「翻訳メモ」）→ その瞬間に「翻訳日時」が入る
        ▼
② エンジニア：White・Color・pts と「作業の分け方」「時間入力者」を書く → 「時間入力日時」「合計」が自動で入る
        ▼
『案件登録』の灰色の列に読み戻し、状態が 記入中 → 翻訳待ち → 時間計算待ち → 時間入力済み と進む
連絡文の期限（登録日時＋計算の期限）を過ぎても時間が空なら Discord で催促（以降1時間ごと・『設定』の時間帯だけ）
        ▼
時間が入った行は、いつもの転記 → 自動登録で工程図へ。『案件登録』のお客様担当者が工程図の「お客様担当者」、納期が納期に入る（作業の担当者＝エンジニアには入れない）
```

- 翻訳日時・時間入力日時は、入力シートを編集した瞬間に入る（編集トリガー `onStaffEdit`。「0. かんたん初期設定」か「自動実行を始める」で設定される）。トリガーが動かなかったときも、30分ごとの自動実行で入る。
- 工程図で決まった納品名は、工程図が `data/deliveryNames`（取込キー → 納品名の配列）にまとめて書き出し、30分ごとの自動実行で『案件登録』と入力シートの「納品名」列に表示する（工程図で納品名を直すと追従）。
- 『案件登録』は、会社コード・案件番号・視点・新規or修正がそろった時点ですぐ入力シートへ写す（管理者シートの編集トリガー `onAdminEdit`。ほかの処理と重なったときは30分ごとの自動実行で写す）。
- 「連絡文」列に、エンジニア・通訳へ送る文が自動で入る（同じ社内案件名・同じ入力日の行は1通）。ひな形は『設定』の「登録時の連絡文」（既定：`{社内案件名}の資料を共有します。／{サーバーリンク}／{計算期限}までに制作時間の計算をお願いします。`）。使える文字は {社内案件名} {社外案件名} {サーバーリンク} {視点一覧} {視点} {パターン} {お客様担当者} {納期} {新規or修正} {通訳へのメッセージ} {登録日時} {計算期限}。{計算期限} は『案件登録』の「登録日時」（登録Noが付いて入力シートへ写した日時）＋『設定』の「制作時間の計算の期限（登録から・分）」（既定 75 分＝1時間15分）を「11/3 15:15」の形で入れる（時刻はベトナム時間）。2つのシートのタイムゾーンもベトナム時間（Asia/Ho_Chi_Minh）にする（「0. かんたん初期設定」で合わせる。2026-11-03 に実際の2ファイルを America/Los_Angeles から変更済み）。メニュー「連絡文をコピー」で、選んだ行の文をコピー・Discord へ送信できる。
- 連絡文のコピー：『登録一覧』の E 列「コピー」にチェックすると、その行の案件の連絡文（エンジニア向け・通訳向け）の画面が開く（チェックはすぐ外れる。メニュー「連絡文をコピー」と同じ画面）。同じ案件・同じ登録日の視点（例 R0001〜R0003 が REN.50 の EX1・EX2・IN1）は、どの行にチェックしても「連絡文」列と同じ1通にまとめて出る（登録No は視点ごとのまま）。開いた時点でエンジニア向けの文が選ばれているので、⌘C（Windows は Ctrl+C）でコピーできる。Google のダイアログはクリップボードへの書き込みが許されていないため、「コピー」ボタンが効かない環境でも ⌘C で使えるようにしてある（2026-11-03）。
- 手動連携：『案件登録』の「今すぐ連携」（チェック）でその行をすぐ入力シートへ写す。『設定』の「今すぐ全部連携（チェックで実行）」で、自動実行（案件登録→入力シート・転記・工程図への登録）をその場で1回動かす。どちらも終わるとチェックは外れる（管理者シートの編集トリガー `onAdminEdit`）。
- 通訳へのメッセージ：『案件登録』の「通訳へのメッセージ」→ 入力シートの「管理者からの連絡」に写す。「通訳向け連絡文」列はひな形『設定』の「通訳向けの連絡文」（{通訳へのメッセージ} が使える）から作る。メニュー「連絡文をコピー」はエンジニア向け・通訳向けの2つを出し、それぞれコピー・Discord へ送信できる。
- 「作業の分け方」（例 `White＝躯体 3h／家具1 2h／家具2 1h　Color＝外壁 2h`）は『連携』の「作業の分け方」列にも転記され、工程図では作業ごとのステップ（ホワイト（躯体）…、externalId は `…::white#1` のように番号付き）に分けて登録する。分けた2つ目以降は納品に数えない（納品名は同じ）。合計が時間と合わない・分けずに登録済みのときは分けずに登録し、「結果」に理由を書く。
- 担当者（作業をするエンジニア）は『連携』の担当者 → その視点の前回の担当者 → 『設定』の「既定の担当者（ホワイト／カラー／pts／写真合成・モデル・VR・動画）」→「既定の担当者」の順。
- 工程図で「サポート（分担）」した作業（`hoursLocked`）は、シートから送り直しても時間を戻さない。
- 入力シートの「合計」と『案件登録』の「社内案件名」「合計」はシートの式。スクリプトは値を書かない（入力シートへ行を足すときも、写す列と登録Noだけを書く）。
- 実際の2ファイル（工程図_エンジニア入力シート・工程図連携_管理者用）は 2026-11-02 にこの形へ更新済み。スクリプトを貼り直したら「0. かんたん初期設定」を1回押して、編集トリガーと30分ごとの自動実行を入れ直す。
- 入力シートの行を消すと、『案件登録』の状態が「入力シートに無い」になる（勝手に写し直さない。もう一度写したいときは『案件登録』の登録Noを消す）。
- エンジニアが入力シートに直接書いた行（登録No なし）も、これまでどおり転記・登録される。

#### Discord の設定（最初に1回）

1. Discord で通知を送りたいチャンネルの「チャンネルの編集」→「連携サービス」→「ウェブフック」→「新しいウェブフック」→「ウェブフックURLをコピー」
2. 連携シートのメニュー **工程図連携 → Discord 通知の設定（Webhook URL）** に貼り付けて OK（URL はスクリプトプロパティにだけ保存。シート・リポジトリには書かない）
3. メニュー **Discord 通知のテスト送信** で届くか確かめる

## 2. 最初に1回だけ行うこと

### 2-1. シートの置き場所と共有

- 管理者用の「工程図連携」と、エンジニア用の「工程図 エンジニア入力シート」は **別のファイル** です。

- 「工程図 エンジニア入力シート」は、制作メンバー（エンジニア）に **編集** 権限で共有してください。
- スクリプトを動かす Google アカウント（kei.n412）に、次の2つの権限が必要です。
  1. 「工程図連携」の **編集** 権限
  2. 「工程図 エンジニア入力シート」の **編集** 権限（見出し・プルダウン・記入ルールを整えるため）
- kei.n412 は工程図の Firebase プロジェクトのオーナーなので、**Firebase 側の追加登録は不要** です。
- 30分ごとの自動実行は、「0. かんたん初期設定」を押したアカウント（kei.n412）の権限で動きます。

### 2-2. スクリプトの貼り付け

3. 左の歯車（プロジェクトの設定）→ **「appsscript.json」マニフェスト ファイルをエディタで表示** にチェック。

4. 保存（フロッピーのアイコン）。
5. シートに戻って **再読み込み** すると、上のメニューに **「工程図連携」** が出ます。

### 2-3. かんたん初期設定（ボタン1回）

   - エンジニア入力シートを整える（下の 2-4）

4. すべて **✓** なら準備完了です。**✗** があれば、その行に書いてある対処をしてから、もう一度押してください（何度押しても安全です。列・タブ・顧客マスタの会社・自動実行が増えることはありません）。

### 2-4. エンジニア入力シート（「0. かんたん初期設定」で整う内容）とエンジニアへの共有

「0. かんたん初期設定」（または メニュー「エンジニア入力シートを整える」）を押すと、エンジニア入力シートが次の形になります。何度押しても同じ結果です。

- 『入力シート』タブ
  - 2行目の見出しを **「日本語」＋改行＋「ベトナム語」** の2段にする（例「会社コード / Mã công ty」）。1列目の見出しが「社外案件名」になっていても、案件番号のすぐ左の列は「会社コード」として読み、見出しを直します。
  - 見出しに2か国語の注記（セルにマウスを乗せると出る説明）、1行目に案内（書き方は『記入ルール/説明』タブ）。
  - 3行目から下（1000行分）にプルダウンを付ける。見出しまでの2行は固定表示。
- 『記入ルール/説明』タブ：書き方・視点コード表・記入例を **日本語とベトナム語の併記** で書き直します（手で書いた内容は上書きされます）。
- 9/21 に配った古い書き方のタブ（『Untitled』など）には触りません。不要なら手で削除してください。

| 列 | 書き方 | 入力のしかた |
|---|---|---|
| 会社コード / Mã công ty | REN・RIC など | プルダウン（『会社マスタ』の案件コードの英字部分。「入力シートに出さない」にチェックした表記ゆれの行は出ない）。リストに無い値も入れられるが警告が出る |

| 新規or修正 / Mới / Sửa | その視点の初回依頼は「新規 / Mới」、2回目以降はすべて「修正 / Sửa」 | プルダウン（リスト以外は入れられない） |
| 視点 / Góc nhìn | 『視点マスタ』のキーワード＋番号。外観目線視点① EX1 / 内観目線視点① IN1 / 外観鳥瞰 EXCB1 / 内観鳥瞰 INCB1 / モデル（外観部）EXM1 /（内観部）INM1 / 外観写真合成 EXP1 / 内観写真合成 INP1 / VR1 / 動画 VIDEO1。①と末尾の数字は同じ | プルダウン（『視点マスタ』のキーワードごとに 1〜10、IN は 1〜20）。リストに無いコードも入れられる（その行は「要確認」になる） |

### 2-9. （任意）コマンドでスクリプトを反映する（clasp）

2-2 のコピー＆貼り付けの代わりに、手元のパソコンのターミナル（Claude Code など）から1コマンドで `sync/Code.gs` と `sync/appsscript.json` を Apps Script に反映できます。`Code.gs` を直すたびに貼り付け直す手間がなくなります。

最初に1回だけ：

1. https://script.google.com/home/usersettings を kei.n412 のアカウントで開き、「Google Apps Script API」を **オン** にする。
2. 「工程図連携」の Apps Script を開き、左の歯車（プロジェクトの設定）→ **スクリプト ID** をコピーする。
3. リポジトリの一番上にある `.clasp.json.example` をコピーして `.clasp.json` という名前にし、`scriptId` にスクリプト ID を貼る。
   `.clasp.json` はリポジトリに入れません（`.gitignore` 済み）。
4. `npm run gas:login` を実行 → ブラウザで kei.n412 を選んで許可する。
   ログイン情報はホームフォルダの `.clasprc.json` に保存されます。**他人に渡さない・リポジトリに入れない** でください。

反映するとき：

- `npm run gas:push` を実行する。送るのは `sync/Code.gs` と `sync/appsscript.json` の2つだけです（`.claspignore` でテストなどは除外）。
  Apps Script 側にある他のファイル（最初からある「コード」や、誤って作ったファイル）は消え、この2つだけになります。
- 反映したらシートを再読み込みします。`appsscript.json` の権限が増えたときは、次にメニューを押したときに承認画面が出るので許可します。
- クラウド上の Claude からは Google にログインできないため、`gas:push` は手元のパソコンで実行します。

## 3. 毎日の使い方

### 自動で動くこと（30分ごと）

1. 入力シートに新しい行・変わった行があれば『連携』タブに反映します（変わりが無ければ何も書きません）。
   新しい行の **「入力日」に転記した日** が入ります（あとで変わりません。内容が変わった日時は「転記日時」）。
   記入途中の行（案件番号・新規or修正・時間が空）は取り込まずに待ちます。
2. 状態が **「未送信」**（自動判定がすべてできた行）で、最後に変わってから **25分** たった行を工程図に自動登録します。
   「工程図へ」にチェックが入った行（人が確認済み）も登録します。登録が済むと状態は「登録済み」、「工程図へ」のチェックは外れ、「結果」は「自動登録：新規○件…」になります。
3. 『設定』の「最後の自動実行」に日時と結果を書きます。止めたいときはメニュー **自動実行を止める**（再開は **自動実行を始める**）。すぐ動かしたいときは **自動実行（30分ごと）を今すぐ1回動かす**。

### 管理者がすること

1. 状態が **「要確認」** の行：「結果」列の理由を見て、社外案件名・会社名・区分・種類・ステップ種類 を直し、**「工程図へ」にチェック** → 次の自動実行で登録されます（すぐ登録したいときはメニュー **2. 工程図へ送信**）。二重入力なら「対象外」にチェック。
2. 状態が **「更新あり」** の行（登録後にエンジニアが時間などを直した）：内容を見て **「工程図へ」にチェック** → 工程図の未完了ステップの時間などを更新します（自動では更新しません。行の消し方によって別の行の中身がずれることがあるため）。
3. 状態が **「エラー」** の行：理由を直して「工程図へ」にチェックし、メニュー **2. 工程図へ送信**（エラーの行は自動では送り直しません）。
4. 必要に応じて 納期・お客様担当者・担当者（社内担当者）・メモ を入れます。**登録前に入れたものが工程図に入る** ので、「未送信」の行に入れたいものがあるときは、転記から25分以内に入れるか、『設定』の待ち時間を長くしてください。
5. 金額（売上・見積・請求）は工程図の請求パネルで入力します。

### 状態の意味

| 状態 | 意味 | 次にすること |
|---|---|---|
| 未送信 | 自動判定が全部できた。自動登録を待っている | 何もしなくてよい（25分後の自動実行で登録）。登録したくない行は「対象外」に |
| 要確認 | 社外案件名・会社名・種類のどれかが決まっていない、2回目以降なのに「新規」、入力シートから一度消えてまた出てきた | 直してから「工程図へ」にチェック（二重入力なら「対象外」） |
| 更新あり | 登録後にエンジニア側の時間・社外案件名・新規or修正などが変わった | 内容を見て「工程図へ」にチェックすると、未完了ステップの時間と案件名・会社名・区分・納期・社外視点名だけ更新 |
| 登録済み | 工程図に入っている | 何もしなくてよい（送り直したいときは状態を「更新あり」にして「工程図へ」にチェック） |
| エラー | 送信時に不備があった | 「結果」列の理由を直し、「工程図へ」にチェックして「2. 工程図へ送信」 |
| 元シートから消えた | 入力シートで行が消えた・書き換えられた（視点・パターンなどが変わると別の行になる）／旧レイアウトで完了チェックが付いた。**登録済みの行が消えた場合、工程図のタスクは残る**（「結果」に書く） | 登録済みだった行は、不要なら工程図側でタスクを削除 |

## 5. 自動実行（30分ごと）のしくみ

- 「0. かんたん初期設定」で、関数 `autoRun` を30分ごとに動かすトリガーが1つ作られます（Apps Script の左の時計アイコンで確認できます。何度押しても1つだけ）。
- 1回の自動実行でやること：①転記（入力シートに変わりがあるときだけ書く）→ ②自動登録（対象の行があるときだけ工程図にアクセス）→ ③『設定』の「最後の自動実行」に結果を書く。
- 自動登録の対象：状態が「未送信」で、転記日時から25分たち、エンジニアが打ち直している最中でない行／「工程図へ」にチェックがあり、状態が 要確認・未送信・更新あり の行。エラー・登録済み・元シートから消えた・対象外の行は送りません。
- 待ち時間（初期値25分）の例：10:05 にエンジニアが行を書く → 10:30 の自動実行で管理者シートに転記（未送信）→ 11:00 の自動実行で工程図に登録。
  10:40 にエンジニアが時間を直した場合は、11:00 に直した内容で転記し直し、そこから25分待って 11:30 に登録（間違った内容のまま工程図に入らない）。
  書いてから工程図に入るまでは、おおむね30分〜1時間です。待ち時間を 0 にすると、転記と同じ回に登録します（書いてから30分以内）。
- 手で押した転記・送信と自動実行が重なったときは、あとから来た方が待つか見送ります（二重登録しない）。
- 自動実行でエラーが起きると、『設定』の「最後の自動実行」にエラーの内容が出ます（Google からトリガーの失敗メールが届くこともあります）。
- 止める：メニュー「自動実行を止める」。再開：「自動実行を始める」。自動登録だけ止める：『設定』の「自動登録」を「しない」。

## 工程図が止まらないための読み取り対策（2026-11-06）
