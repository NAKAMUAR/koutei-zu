| 項目 | 内容 |

| スクリプト | `sync/billing/Billing.gs`・`sync/billing/appsscript.json`（「工程図連携」の Code.gs とは別。雛形のファイルに貼る） |

## 1. できること（メニュー「帳票」）

| メニュー | 内容 |
|---|---|
| 1. 工程図から読み込む（今のタブ） | 工程図の案件（金額の入った作業がある案件）を選ぶと、宛先・件名・明細（1作業＝1行・数量1・単価＝作業の金額）を今のタブに書く。請求書は未請求の作業だけ（「請求済みの作業も入れる」で全部） |
| 2. PDFで発行（今のタブ） | NO（見積 E／発注 O／請求 I-YYYYMM-NN。アプリの帳票と続きの番号）と発行日を空なら入れ、今のタブだけを A4 縦の PDF にして、雛形と同じフォルダの「工程図_帳票PDF」に保存。『発行一覧』タブに記録し、工程図の帳票一覧（`data/bill_{id}`、`source: 'sheet'`・`pdfUrl`）にも登録。請求書は読み込んだ作業を「請求済み」（`invoiceCheckedAt`）にする |
| 入力を空にする（今のタブ） | NO・発行日・宛先・件名・支払期限・明細だけ消す（計算式・発行元・振込先・備考はそのまま） |
| 発行一覧を開く | 『発行一覧』タブ（発行日時・種類・NO・宛先・件名・合計・PDF・読み込んだ案件） |

- 手で書いても使える（読み込まずに明細を書いて「PDFで発行」）。
- 書き込む位置は `BL_LAYOUTS`（雛形の行・列を変えたらここも直す）：
  - 見積書：NO BA4・発行日 BA6・宛先 E11・件名 M17・明細 32〜45行（項目 E・数量 AG・単価 AO・金額 AZ）・合計 AZ49
  - 発注書：NO N5・発効日 N7・お客様（発行元側）K17・件名 D18・明細 30〜39行（項目 B・数量 I・単価 J・金額 M）・合計 M43。金額の式が4行分しか無いので、書いた行には式を足す
  - 請求書：NO N5・発行日 N7・宛先 B12・件名 D18・支払期限 D19・明細 30〜39行（日付 B・項目 C・数量 I・単価 J・金額 M）・合計 M43
- 明細が行数を超えたら、最後の行に「ほか N件」としてまとめる。
- 請求書の軽減税率（8%）は扱わない（雛形の 8% 欄は 0 のまま）。
- 住所・振込先は雛形のシートにだけある。コードには書かない（公開リポジトリ）。

## 1-2. 売上総合報告書（毎月）

- 雛形：月の報告書（例「売上総合報告書(2026.10月分) リノベる・オフィスコム集計版（コピー）」 https://docs.google.com/spreadsheets/d/1-pddTLkzAzh1O0dCDDNOTY2XaZ6kHnjjAfTpETvvdG8/edit ）を、メニュー「売上総合報告書：雛形を取り込む（最初に1回）」で雛形ファイルに『売上総合報告書（雛形）』としてコピーし、案件の記入（D〜L・O〜W・AA〜AB 列）を消す。元のファイルは変えない。計算式（M・N・X・Y・Z 列、上の集計）と見出し・プルダウンはそのまま。
- 毎月：メニュー「売上総合報告書：月を選んで作る」→ 月（2026-11 など）→ 雛形をコピーして『売上総合報告書(2026.11月分)』タブを作り、工程図の**売上登録表**（`data/sales_YYYY-MM`）のその月の行を流し込む。表題（B2）・最終更新日時（X4）が入り、最終チェック（W4）は外れた状態。
  - 区分は見出し（B列の「1.」「３.」など）から自動で探す。行の区分（オフショア国内／国際・ラボ国内／国際）と会社名で入れる区分を決める（ラボは見出しのかっこ内の会社名。オフィスコムの「図面」は図面作成の区分）。
  - 制作種類・制作名・完了の有無などのプルダウンは選択肢に合わせて入れる（「内観目線視点③」→「内観目線③ (cut …)」）。合わないものは備考（AB列）に「制作名：…」で残す。
  - 区分の行が足りない行・入れる区分が無い行（ラボで見出しに会社名が無い会社）は、結果の画面に一覧で出す（手で足す）。
  - どの月に入るか（25日の締めなど）は、アプリの売上登録表の月のまま。ずれていればアプリで直してから作り直す（同じ月をもう一度作ると置き換えを確認する）。
- 月のタブで「2. PDFで発行」→ 横向きの PDF を「工程図_帳票PDF」に保存し『発行一覧』に記録。

## 2. 設置（最初に1回。kei.n412@gmail.com で）

1. 雛形のファイルを開く →「拡張機能 → Apps Script」。
2. 「コード.gs」の中身を全部消し、`sync/billing/Billing.gs` の全文を貼って保存。
   （全文：https://raw.githubusercontent.com/NAKAMUAR/koutei-zu/main/sync/billing/Billing.gs ）
3. 歯車（プロジェクトの設定）→「"appsscript.json" マニフェスト ファイルをエディタで表示する」をオン → `appsscript.json` に `sync/billing/appsscript.json` の中身を貼って保存（工程図と Drive を使う許可。省くと工程図に届かない）。
4. 雛形のファイルを再読み込み → メニュー「帳票」→ どれかを押す → 承認（「詳細」→「安全ではないページに移動」→ 権限を「すべて選択」→「許可」）。
5. 請求書タブで「1. 工程図から読み込む」→ 案件を選ぶ →「2. PDFで発行」で動作確認。

- 工程図への読み書きは実行したアカウントの権限（`ScriptApp.getOAuthToken()`）。工程図の Firebase オーナー（kei.n412）で承認すること。別のアカウントだと工程図に届かず、PDF だけ作られる（結果の画面に理由が出る）。
- clasp（`npm run gas:push`）は「工程図連携」用。帳票のスクリプトは送らない（`.claspignore` で除外）。

## 3. アプリ側

- 帳票一覧で、シートで発行した帳票に「PDF」ボタンが出る（Drive の PDF を開く）。
- 請求書は「送付済み」で登録される。売上登録表との紐付けは、これまでどおりアプリでステータスを変えたときに行われる。

- 2026-11-03：売上総合報告書を足したため、権限が「このファイルだけ」から「スプレッドシート」に広がった（雛形の取り込みで別のファイルを開くため）。前の版で承認済みなら、もう一度承認が出る。
