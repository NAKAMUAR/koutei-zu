### 3.2 スケジューラ `scheduleTasks(tasks, settings, projectOrder, now)`

**処理フロー：**

```mermaid
flowchart TD
    A["active / done / suspended に分離<br/>（suspended は対象外）"] --> B["作業順ソート<br/>案件順→並び順→ホワイト→登録順"]
    B --> C["doneFloor算出<br/>完了実績(actualEnd)から着手下限"]
    C --> D["事前パス：manualStart指定を枠予約（差し込み）"]
    D --> E["各タスクを順に配置"]
    E --> F["effectiveDuration算出<br/>＝ 残作業（制作時間 − 完了時間）のみ"]
    F --> G["fillTaskSlotsで空き枠へ充填"]
    G --> H["終了時刻・後続下限を更新"]
    H --> I["done を review / doneFinal に分割"]
    I --> J["{ active, done, review, doneFinal, suspended }"]
```

**戻り値：**

| キー | 内容 |
|---|---|
| `active` | 配置済みの進行中タスク（開始・終了予定つき）。 |
| `done` | 完了済みタスク全体。 |
| `review` | `done` のうち `reviewState === 'waiting'`（確認待ち）。 |
| `doneFinal` | `done` のうち確認も済んだもの（完了タブ表示用）。 |
| `suspended` | 制作中断中（スケジュール対象外）。 |

**主要サブロジック：**

- `effectiveDuration(task)` … **残作業時間 `hours - completedHours` をそのまま所要時間とする**（開始予定どおりに配置）。
  - 経過時間では終了予定を膨張させない（未記録のまま時間が経っても枠は伸びない）。0.5h タスクは常に 0.5h 枠。
  - 遅れの反映は「完了時の実終了時刻（actualEnd）」入力時のみ。`doneFloor` 経由で後続タスクの着手下限が後ろへずれる（要件F-08）。
- `fillTaskSlots(task, eTs, durationHours)` … `eTs` 以降の空き枠へ `durationHours` を分割充填。`manualEnd`（開始より後の時のみ有効）でその時刻打ち切り。
- `baseTsOf(assignee)` … 起点（startDate+startTime）とdoneFloorの遅い方。
- `lastEndByAssignee` / `vpLastEnd[vkey]` … 担当者の直前終了・同視点の工程順の下限。

**vkey（視点キー）：** `` `${assignee}::${projectName}::${viewpointName}` ``

### 3.8 ステップ→売上の自動同期（`src/viewpoint/salesSync.js`）

**不変条件：**

1. 生成行は `srcVp`（視点キー）・`srcRound`（`step:{taskId}`）で識別する。**手動行（src 無し）は一切触らない。**
2. source が所有するフィールド（`company` / `person` / `projectName` / `prodType` / `prodName` / `prodAmount` / `inHouseOutsourcer` / `externalOutsourcer` / `outsourceVND` / `orderDate`）のみ毎回上書きする。
3. ユーザーが編集する項目（区分・納品日・請求/入金・備考・枚数など）は保持する。
4. 対象ステップが消えた生成行は削除する（＝視点から金額を消すと売上行も消える）。
5. 計上月は「ステップの依頼日（`stepRequestDate`）の月」。日付が無ければ `fallbackMonth`。

**売上区分の判定：**

| 契約形態（contractType） | 売上エリア（salesArea） | 区分 |
|---|---|---|
| offshore | domestic | `offshore_dom` |
| offshore | intl | `offshore_intl` |
| lab（既定） | domestic | `lab_dom` |
| lab（既定） | intl | `lab_intl` |

## 4. 主要処理シーケンス

### 4.1 タスク登録（新規）

```mermaid
sequenceDiagram
    participant U as 利用者
    participant V as InputView
    participant A as App.handleSubmit
    participant S as simulateFormSchedule
    participant DB as tasksStore

    U->>V: フォーム入力 → 登録
    V->>A: handleSubmit()
    A->>S: 試算（開始移動・納期超過）
    alt 移動 or 納期超過あり
        A->>U: 確認モーダル表示
```

### 4.2 進捗入力 → 終了予定の自動調整

```mermaid
sequenceDiagram
    participant U as 利用者
    participant R as StepRow
    participant A as App.addProgress
    participant M as useMemo(scheduled)
    U->>R: +1h / 直接編集
    R->>A: completedHours 更新
    A->>DB: 差分保存
    Note over M: tasks/now 変化で再計算
    M->>M: scheduleTasks（残作業＝hours−completedHours で枠を取り直す）
```

### 4.3 完了 → 確認待ち → 完了タブ

```mermaid
sequenceDiagram
    participant U as 利用者
    participant D as CompleteDialog
    participant A as App
    participant S as 確認待ちセクション

    U->>D: 視点完了（実終了時刻を入力）
    D->>A: status=done, actualEnd, reviewState='waiting'
    A->>S: 確認待ちへ表示
    alt 追加修正あり
        U->>S: 修正メモを記入

    else 進行中へ戻す

    A->>A: reviewState を外して完了タブへ
```

```mermaid

    P->>A: 新終了予定を入力
    A->>A: 最後のステップを特定
    A->>A: 差分稼働時間を加算 + manualEnd を新時刻へ更新
    A->>DB: 保存（delays履歴追加）
    Note over A: manualEnd更新で終了予定が動き再表示ループを防止
```

### 4.5 ステップの金額入力 → 売上行の自動生成

```mermaid
sequenceDiagram
    participant U as 利用者
    participant R as StepRow
    participant A as App
    participant Sync as salesSync
    participant DB as salesStore

    U->>R: ステップに制作金額 / 外注費VND を入力
    R->>A: setStepMeta()
    A->>Sync: 対象月の売上データと突き合わせ
    Sync->>Sync: srcRound=step:{taskId} の行を生成／更新／削除<br/>（手動行・ユーザー編集項目は保持）
    Sync->>DB: salesStore.set('YYYY-MM', 月データ)
```

## 8. エラーハンドリング・例外設計

| 事象 | 対応 |
|---|---|
| 保存失敗（書き込み例外） | `console.error` ログ＋`notify()` でトースト表示。楽観的更新済みのため画面は維持。 |
| onSnapshot不発（保険） | 15秒タイムアウトで `tasksLoaded` を立て、ローディングを解除。「データ更新」ボタンで手動再取得できる。 |
| 入力バリデーション | 案件名必須、制作時間≧0、完了≦制作時間、時間帯の前後関係等をフォーム側で検証し `notify()` で表示（`alert` は使わない）。 |
| 名称変更の波及 | スコープ外の同名案件タスクへ反映する確認（`needsRename`）を挟む。 |
| 外部シート削除整合 | `deletedExternalIds` に記録し再同期での復活を防止。 |
| 誤削除 | 削除系の操作はトーストに「取り消し（undo）」を付ける（`docs/07` の原則）。 |
| 移行の二重実行 | `migrationDone`（useRef）と `migratedFromRound`（冪等キー）で一度きりに抑える。 |

## 9. テスト方針

- 純粋ロジック（`scheduleTasks` / `simulateFormSchedule` / `dayWorkSlots` / `salesSync` 等）は `src/lib/`・`src/viewpoint/` に分離済みなので、Nodeスクリプトから直接 import して境界値検証できる。
- スプレッドシート連携の純ロジックは `node sync/test/logic.test.mjs` で検証する（22ケース）。
- 代表検証ケース：
  - 進捗連動：4hのタスクで完了2h→残り2h枠、完了3h→残り1h枠（開始位置は動かない）。
  - 実績連動：完了時に actualEnd を入れると、後続タスクの着手がその時刻以降へずれる。
  - 残業：10h案件に残業17:00–19:00で当日19:00終了、残業なしは翌営業日へ。
  - 欠勤・祝日：終日欠勤日・登録済みの祝日には配置されない。
  - 納期：終了予定が納期日超過時に違反検出。
  - 遅延：新終了予定で `manualEnd` 更新し再表示ループが解消。
  - 売上同期：ステップの金額入力で行が生成され、金額を消すと行が消える。手動行は変化しない。
- ビルド検証：`npm run check`（ESLint）→ `npm run build` の順で必ず通す（build が check を自動実行）。
- UIに触れた場合は `npm run preview` でログイン画面が描画されることを最低限確認する（モジュールレベルのクラッシュ検出）。

## 10. 既知の制約・今後の課題

未実装項目の詳細は `docs/06_未実装機能設計書.md` を参照。主な制約は次のとおり。

- 稼働時間は全員共通。**担当者ごとの稼働時間（日本／ベトナムの時差）は未対応**（項目10）。
- 請求書ステータスと売上登録表の請求/入金日は**二重入力**（項目2）。
- 見積書の工程予定表は固定7列でラベル編集不可（項目3）、アングルページに画像を貼れない（項目4）。
- 外注費集計の対象者（`OUTSOURCERS`）がコードにハードコードされている（項目5）。
- タスクメモの通知はアプリを開いている間のみ（項目9）。
- 旧データのバックアップキー（`*_backup`）の削除導線がアプリ内に無い（項目7）。
- LINE等の外部進捗連携は将来検討（現状は手動入力）。
